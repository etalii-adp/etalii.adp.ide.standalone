# Tasks Document

One worktree for the whole spec: `.claude/worktrees/ansible-ref` — deliberately short, because the Windows MAX_PATH failure mode (apphost never produced, `dotnet test` reporting zero tests) is triggered by long worktree names.

**Already delivered, no task here.** Requirement 5.2's central `--color-warning` token landed via the rdf-diagram merge `3e130bba` — two definitions in `src/client/src/index.css`, one per mode — because that module needed a caution colour for its truncation banner and reached this spec's conclusion independently. Nothing below adds it; task 1.1 only removes ansible's now-pointless literal fallbacks beside it.

**Gate discipline, every gate task.** Set `MSBUILDDISABLENODEREUSE=1` and `DOTNET_CLI_USE_MSBUILD_SERVER=0` before running: the intermittent `0xC0000005` test-host deaths were diagnosed as concurrent sessions' MSBuild nodes colliding, and several agents gate concurrently. Capture the exit code before any pipe — redirect to a log, take the code on the very next line, judge the variable, and read the log only to explain a failure. `dotnet test ... | tail -5` followed by reading the status reads the pipe's code, not the suite's, and a zero-test run exits 5 having printed no failures at all.

**Pattern citation, not re-derivation.** The layout mechanism has four shipped consumers (databricks built it, helm shipped it, rdf uses it, the core command underpins them). Helm's implementation proved the full cycle live: a drag lands in the registration, undo restores it, and the subject's own files stay byte-identical, with dragged and computed positions sharing one render path because the registration lives inside the watched folder. Ansible has exactly that shape. Cite it; do not re-verify it.
