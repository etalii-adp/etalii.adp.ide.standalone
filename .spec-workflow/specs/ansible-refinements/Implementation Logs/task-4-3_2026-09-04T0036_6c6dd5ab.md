#### Integration
- **Description:** The node drag called setPointerCapture on the svg. A pointer capture retargets subsequent pointer events including pointerup, and the browser fires click on the common ancestor of the pointerdown and pointerup targets - so the click landed on the svg, not the node, and click-to-select silently stopped working. Every unit test passed throughout because jsdom implements no pointer capture at all; the stub that makes the drag tests runnable is exactly what hides the consequence. Fixed by capturing on the node element (event.currentTarget) and releasing from whichever element took the capture. Guarded twice: a unit test asserting which element is asked to capture (jsdom can see that), and a tests.md check asserting that a click selects (only a real browser can show that).
- **Frontend Component:** undefined
- **Backend Endpoint:** undefined
- **Data Flow:** pointerdown on node -> capture on node -> pointermove/up retarget to node -> bubble to svg handlers -> click fires on node
