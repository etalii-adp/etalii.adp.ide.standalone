# Implementation Log: Task 6

**Summary:** dependency-graph implements the view-delta loop, both halves. Merged into develop at bdaa0d1e (work commit afa8ec0f on a detached worktree at 4fd8ea89).

Backend: DependencyGraphElementMapper gains Visible(model, viewport) - a node whose box (NodeWidth 160 x NodeHeight 36, y from DependencyGraphRows.ToY) intersects the rectangle, plus every relation both of whose ends are in, because a curve follows its endpoints and has no box; document order preserved on both passes so one viewport yields one sequence. DependencyGraphSession.UpdateView now recomputes the previously visible set from the viewport it last held (not a remembered field, which would diff against elements a document change may have removed), then emits Add for what appeared and Remove for what left - the Add-then-Remove order both reference implementations use, which the design corrected Requirement 4.3 to. Render() is viewport-aware too, so a save after a report re-delivers what is in view rather than undoing the cull; _viewport starts Unbounded so a client that never reports still opens with the whole graph.

Client: useDependencyGraphStream exposes reportView built with viewReportOf on its own client (this module does not use useDiagramStream - Requirement 3.6). DependencyGraphCanvas is a pixels-per-unit canvas rather than a viewBox one, so it converts at its own call site: visibleRect() derives the rectangle in module units from startX/panY/pixelsPerUnit/verticalScale and the measured surface, with documented defaults for the unmeasured/jsdom case (a zero-sized rect would report a viewport admitting nothing). useViewReport is keyed on the four derived numbers, so pan, zoom, scrollbar drag and programmatic fit all reach the report the same way.
