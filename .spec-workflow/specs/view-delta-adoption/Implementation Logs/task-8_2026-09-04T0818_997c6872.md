# Implementation Log: Task 8

**Summary:** sparql closes the view-delta loop, both halves, with the OnDocumentChanged hazard designed in rather than fixed afterwards. Backend: SparqlSession gains a _viewport defaulting to DiagramViewport.Unbounded, UpdateView diffs the visible set across the change and emits Add for what appeared then Remove for what left, and — the part that matters — Render() itself is viewport-aware, so the change path and the view path go through one place and an ordinary edit can never re-send what the viewport just culled. Visibility is a new module-local SparqlElementMapper.Visible: regions whose frame the rectangle touches, nodes whose BOX touches it (SparqlLayout.NodeWidth/NodeHeight promoted from private to public for exactly this, since testing a bare anchor point would cull a node that is half on screen), the Ansible one-hop rule for edges, and — found by two existing tests failing on the first run — an unconditional pass-through for anything with no position at all, the header band being the case that matters. No shared backend helper. Client: useSparqlStream exposes reportView via the shared viewReportOf; SparqlCanvas is pixels-per-unit rather than viewBox, so it converts to a rectangle at its own call site the way TimelineCanvas does, keying useViewReport on the converted rectangle so a pan and a zoom showing the same span report once and a resize still reports. Verification, and the part worth reading: the view-diff test was proven to fail against a return []. The interaction guard needed THREE attempts to become non-vacuous — it first re-called UpdateView (which a broken UpdateView makes trivially true), then used a variable rename that changed element ids so the culled id no longer existed, and only an additive edit preserving every id makes it discriminate; it now fails under a viewport-blind Render(), as does the view-diff test. An over-assertion of mine was also removed: requiring a delta to arrive would have been asserting the bug, since an edit landing outside the narrowed viewport correctly produces nothing.
