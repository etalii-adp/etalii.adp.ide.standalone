# Implementation Log: Task 5

**Summary:** Committed as 56439d22 with an amendment in 59fe33f1, landed on develop in d8adc1e5.

DiagramDefinition.acyclic declares sets of relation types within which a directed cycle is not admitted, and connectVerdict gained a breadth-first walk over model.connections: a target is refused when a directed path already runs from that target back to the source through edges whose type is in the same set. validateDiagramDefinition rejects a rule naming a relation type the definition does not declare - a typo there enforces nothing and enforces it SILENTLY, because the walk simply never covers that edge and the diagram admits the cycle the author forbade.

A SET RATHER THAN A FLAG, because acyclicity is a property of a set of edges and not of a diagram. A decomposition's containment must form a tree while annotations drawn between the same elements may run any way they like, and a per-relation boolean cannot say that a path alternating between two covered types is still a cycle. Edges outside the set are not traversed at all, so a path that leaves the set is not a path.

BREADTH-FIRST OVER A VISITED SET, NOT A BOUNDED DEPTH. A model may already hold a cycle whatever the definition says - the rule can have been declared after the document was written, or the document written by hand - and a walk that trusted the rule to have been enforced would follow it forever with the pointer still down. Termination is a property of the algorithm rather than of the data, and there is a test driving a model containing B to C to B.

SEEN TO FAIL TWICE, and the second time is the evidence that matters. Against today's code, which runs no walk at all, 3 of the 5 gesture tests failed. Then against a PLANTED early return - if (cardinality !== undefined) return true; ahead of the walk - EXACTLY ONE test failed, the independence one, with the other four green. Four of five cannot see that defect by construction, because every one of them declares no cardinality at all. That measurement is now in the test's own docstring, so a later reader cannot call it redundant.

DETECTORS BOTH WAYS ROUND. The three above detect a rule that does not run. The two that pass against today's code - the identical chain with no set declared, and the chain whose path leaves the set - are the detectors in the OTHER direction: they catch a walk that ignores the declared types, which is the same rule quietly widened to "no cycles anywhere". The validation pair is the same shape: the rejection, and an accepted rule beside it, because a guard that only ever sees a rejection cannot tell a working check from one that refuses everything.

AN ASSERTION ADDED AND REMOVED (59fe33f1). Tracing criterion 5.4's "shall not be offered or highlighted", I added an absence assertion on library-connect-target beside the forbidden-class one. Planting against it showed it never evaluates: the forbidden assertion fails first, and both classes are painted from a single connectHighlight value, so they are mutually exclusive by construction and the new line could not fail while the old one passed. It is gone, and a comment says why the criterion's two clauses are one assertion here. Reaching for the plant instead of trusting the reasoning is the only reason that is a comment rather than a check guarding nothing.
