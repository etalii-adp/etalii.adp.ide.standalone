**Summary:** Committed as 26aeadee, landed on develop in d8adc1e5.

A label declaring wrap: true opens a TEXTAREA over its own text region. Enter there is text the user is typing - neither committed nor prevented, so the browser's default inserts the newline - and Ctrl+Enter or Cmd+Enter commits. Blur commits, Escape cancels, a refusal holds the box open and an unchanged value dispatches nothing: all shared with the single-line field rather than copied, because a second field is the obvious place for one of those to be quietly dropped. The commit is today's label-commit-requested with newlines in the value; no new event.

LabelPlacement.multiline IS STATED BY THE CANVAS, NOT INFERRED FROM THE TEXT. A wrapped label whose current value happens to hold no newline is still a wrapped label, and inferring it would hand the user a field they can type a newline into only once they already have one.

THE EDITOR'S BOX IS THE REGION THE LAYOUT FITTED, read back through the new wrappedLabelRegion rather than a band recomputed from outside. The region and the line count are solved together, so anything that guesses arrives at a different box - and an editor that is not exactly over the text it replaces shows as text jumping the moment it opens. The wrap branch sits ahead of the centred one because a wrapped label typically declares neither offset nor editorBox, which is that branch's own condition. This also closes the editor-placement layoutLabels call site task 3 deliberately left open: it now passes the shape.

SEEN TO FAIL against the real pre-state, which IS the defect the task names. Seven of the eleven new tests failed: expected 'INPUT' to be 'TEXTAREA'; Enter committing where it must not; and the committed value arriving without the newline, three times over for Ctrl+Enter, Cmd+Enter and blur.

WHICH CHECKS ARE DETECTORS: the tag, the Enter-does-not-commit case, and the two newline-carrying commits. The other four PASS IN BOTH WORLDS and are marked in the files as companions - focus-and-select, Escape dispatching nothing, the placement carrying the whole label text, and an unwrapped declared label still opening over the element. The last is kept deliberately: the wrap branch sits in front of it, and a branch that swallowed the unwrapped case would move every existing declared label's editor with nothing else to say so.

DOCUMENTATION REFRESHED IN THE SAME CHANGE: canvas/label/readme.md said "Enter commits whatever is typed" flatly, which this makes false. It now says "in the single-line field" and carries a section on the multi-line one.
