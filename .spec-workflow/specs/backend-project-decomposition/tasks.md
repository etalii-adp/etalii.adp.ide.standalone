# Tasks Document

**One developer owns this specification end to end.** The areas are entangled and cannot be fanned out; the landings are independent for ordering and clean merges, not for extra hands. **Developer 3 measured the ground and its `findings.md` (`7955135c`) is the dependency map every task sizes against** — consume it, do not re-derive it.

**Sequenced for a moving `develop`, which is a first-class constraint here.** `develop` takes a commit roughly every two minutes; a backend gate cycle runs 15–45 minutes. **A step that renames a namespace used across the module tree cannot win a fast-forward unaided** — it must land inside a coordinated merge hold the Scrum master arranges. Each task below is marked **[normal]** (lands in ordinary cadence) or **[HOLD]** (wide blast radius — tell the Scrum master before starting it, not when it fails). The wide steps are the proto-namespace migrations and the `Line`-family descent, because both rename types referenced outside the backend.

**Every landing, without exception:** the four gates green on the merged tree (exit codes captured **before any pipe**, `Zero tests ran` read as a broken build), a **fresh-tree build** (the only check that reads a different input than the `obj/` cache — and this spec changes generated code and references at almost every step), and **`jb inspectcode` clean** for the affected projects (it sees the namespace-provider warnings `dotnet format` cannot, and a decomposition produces them at scale). No behaviour change: a test whose meaning shifts is a defect, not an expected edit.

**Worktree.** `.claude/worktrees/bpd` — short, because a long name pushes the deepest project paths past `MAX_PATH` and the symptom is `dotnet test` reporting `Zero tests ran` rather than failing. `MSBUILDDISABLENODEREUSE=1` and `DOTNET_CLI_USE_MSBUILD_SERVER=0` before gating. **Identity at creation**: `git config --worktree user.name "developer-N-backend-decomposition"`, read back with plain `git config user.name` before the first commit. Merge through a **per-agent** scratch worktree, reset/merge/gates/fast-forward chained into one command.

**Namespaces are controlled through `.DotSettings` `NamespaceFoldersToSkip`, not by editing namespaces to match folders** — escaping `_005C` for a separator and `_005F` for an underscore, verified by `inspectcode` because a mis-escaped key parses fine and matches nothing.

**Coverage note — three requirements are discharged other than by a single task, named so the coverage diff does not read them as gaps:**

- **R4.1–4.3 are superseded, not implemented as written.** They require generation *single-owned at the bottom by exactly one project*; the user's later direction (each proto in its owning project, generating a `.Wire` namespace) replaces that, and the approved design flags the supersession in its Overview. Tasks 3, 8 and 10 implement the replacement; the original R4 criteria are intentionally not met, and that is the ratified decision, not an omission.
- **R6.1–6.3 are cross-cutting, discharged on every landing** by the blanket rule above (four gates, fresh-tree build, `inspectcode` clean) and confirmed structurally by task 11 — not claimed by one task because they bind all of them.
- **R2.3 is discharged by the design.** It requires that a judgment about where a shared type belongs be *recorded in the design with its reasoning* — the design does this for the `.Wire` ownership split, the `Line`-family and `SessionContext` placement, and the Common-vs-reachable distinction. Tasks 5, 6 and 7 carry any implementation-time judgment into their logs, but the criterion itself is met by the approved design.
