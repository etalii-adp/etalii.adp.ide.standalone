# Tasks Document

One Developer owns this specification, per CLAUDE.md's one-owner-per-specification rule, and works it in one worktree (`.claude/worktrees/tml`, branch `features/timeline-disl-fbl`). **The order is the design's six steps and it is load-bearing**: the fixtures and the transcript are frozen before anything changes (task 1), the definition is bundled before the reading changes (task 3), and reading changes before writing (tasks 5 and 6), so that a difference in the transcript can be attributed to one change: to the definition, to reading, or to writing.

**Every task is one pull request into `develop` and leaves the four gates green.** A task whose transcript differs in a way this document does not name is not delivered.

**Task 2 is done in etalii-adp/etalii.adp**, through that repository's own pull request, and task 7 has a part there too (the companion `timeline.md`). Task 3 cannot start before task 2 is merged there. Task 2 claims no criterion of its own: it is the etalii.adp half of Requirement 2.1, which task 3 claims when the definition arrives in this repository.

**Which tasks wait, and on what.**

- **Tasks 1, 2 and 4 wait on nothing** and can start now.
- **Task 3 waits on task 2** being merged in etalii.adp.
- **Task 5 waits on the specification `fbl-written-text`** being merged on `develop` (its Requirements 2, 3 and 4, with 5.1 and 5.2), and on tasks 3 and 4. FBL 0.5 itself is merged in etalii.adp (pull request 115); what is missing is the standalone library's part, which is that specification's work and not this one's. Nothing is built on a workaround meanwhile (Q3).
- **Task 6 waits on task 5**, and on `fbl-written-text` Requirement 2.6.
- **Task 7 waits on task 6.**
- **The first half of task 4 (the design's L2) is shared library work.** Every tool of the series that reads a declared binding under a DISL definition needs it, and it is delivered once, by whichever specification reaches its reading step first. Task 4 looks on `develop` first and does not build it a second time.

**The two amendments of the design are ruled, and the tasks are written to the rulings** (ruled by the user in chat, 2026-10-11, the first option of each). Requirement 4.2 keeps the stand-in `TimelineYamlSyntax`, which task 5 adds. Requirement 1.3 names the `undoAll` lines beside Q1 and Q2, which task 6 regenerates with the edit hunks.
