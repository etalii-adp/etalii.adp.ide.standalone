# Implementation Log: Task 6

**Summary:** Task 6 derives the functional decomposition graph's palette, context menus, property rows and deletion confirmation from its bundled definition. FdgDefinition holds functional-decomposition-graph.dis as the library's DislDiagramDefinition with the x-fdg wire ids and derives Menus, Rows and Confirmation; ElementOf finds an element by its written id (host attribute storedId), the first element and else the first connection, as FdgModel does. FdgDisl builds the DISL model from FdgParser's reading (TimelineDisl's shape), cached per parsed model, until the body is read through the binding (task 9). The palette is the library's DislToolboxProvider; FdgToolboxProvider is deleted. FdgContextActionProvider.Discover and FdgContextPropertyProvider.Describe hand out what FdgDefinition derives, and a removal asks the definition's confirmation. The hand-written menus, rows, confirmation and palette moved to Parity/HandWrittenFdg.cs as the oracle; FdgDerivedMenus.Tests and FdgDerivedRows.Tests compare derived with hand-written on every document of the parity corpus (FdgCorpus) and every target the transcript records, readable and read-only. Fork taken: derived with an editable env, because the tool has always offered its menus and editable rows on an entry it could not read; read-only would mark every row read-only. Sabotages, each seen to fail: ReadOnly env (39 row failures), confirmation message (24), element menu taken from the canvas (39); a last-instead-of-first connection lookup changed nothing because no corpus document has a duplicate connection id. The transcript is reproduced byte for byte and not regenerated. Gates on macOS: npm test 0, typecheck 0, format 0, inspect.sh clean, FDG tests 298/298; dotnet test 17903 with one macOS-only failure present on develop too (UndoRedoFlowTests rename undo).
