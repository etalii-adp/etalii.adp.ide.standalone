# Implementation Log: Task 5

**Summary:** WardleyParser reading components, links and pipelines into a WardleyMap. Line-oriented, matching the DSL: one statement per line, one nested construct (pipeline blocks) going one level deep, so there is no scope stack beyond "am I inside a pipeline". It NEVER FAILS - a line it does not recognise is skipped, the document keeps it (Requirement 3.3), and the validator judges what it can (Requirement 14). Keeping the reading and the judging apart is what lets a map with a dangling link still open and render (Requirement 3.5). Coordinates stay in the document's [visibility, maturity] order; the Point2D conversion lives in WardleyAxis alone. The model is a READING, not a resolved model: links name endpoints as strings, a pipeline names its parent as a string, nothing is checked for consistency. Three statement kinds, not five, per the approved correction: WardleyElementKind is Component/Anchor/Submap, and the five decorators (market, ecosystem, build, buy, outsource) are a set on the component; inertia is a separate boolean. TWO REAL PARSER BUGS, both caught by task 2's deliberately awkward fixtures and both now guarded. (1) An unmodelled statement was being MISREAD as a link: "y_axis Value chain->Invisible->Visible" contains two arrows and matched the link expression, which would have put an element on the canvas the document never declared - worse than not modelling the statement at all, and the opposite of Requirement 3.3. Fixed with a KnownKeywords set that skips any statement opening with a DSL keyword, including the ones task 6 models and the ones this spec never will. (2) Pipeline children parsed as nothing: a child carries ONE bracketed number and the coordinate expression required two, so every nested pipeline came back empty. Split into its own single-value expression. A third failure was my test asserting the wrong thing - it forgot the fixture's anchor - and the parser was right; the test was corrected rather than the code. 35 parser tests including a Theory over the whole corpus asserting Parse never throws for anything in it. Verified: 1478 tests pass, format gate exits zero.
