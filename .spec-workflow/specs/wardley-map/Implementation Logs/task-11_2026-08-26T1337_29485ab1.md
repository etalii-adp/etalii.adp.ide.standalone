# Implementation Log: Task 11

**Summary:** The wire contract and the mapper. wardley-map.proto carries the module's element payloads packed into the core Element's Any; no core proto was edited. The payload keeps the DOCUMENT'S OWN visibility and maturity alongside the canvas position, because the property grid shows and edits those numbers directly and reconstructing them from a Point2D would be a second conversion - exactly what Requirement 5.2 forbids. THREE ENUMS MOVED INTO THE PROTO AND THEIR HAND-WRITTEN TWINS WERE DELETED: the generated types collided by name, and the repo already had the answer in ContextPropertyEditor, which is used directly from context.proto - "one name for the wire and for the domain, so there is nothing to map and nothing that can drift". Their documentation moved into the proto too, where both sides read it. WARDLEY_ATTITUDE_KIND_TOWN_PLANNERS rather than TOWNPLANNERS, because protobuf renders the latter as Townplanners. WardleyAxis is the single home of the conversion: x = maturity, y = 1 - visibility, a transposition AND an inversion. Both plausible errors are silent - swapping the pair reads a map sideways, dropping the inversion turns it upside down, and both still render a convincing picture - so it is pinned three ways: a highly visible genesis component must land top-left; ToCoordinate must invert ToPoint exactly (a drag reads a point back into the document, and a lossy pair would nudge components on every touch); and the Genesis/Custom Built boundary must land at x = 0.175, which ties the axis to the evolution bands so neither can drift into disagreement with the other. WardleyElementMapper is where names become identities. A link whose endpoint does not resolve STILL GOES OUT, carrying the names as written, so the canvas can mark the dangling end and the validator can name it. An edit is an Add carrying the element in its new state, never Remove-then-Add, which would make the element momentarily absent and drop the selection on the thing being edited. Pipelines use the existing Group action - the second independent use after mindmap folding, with no new Delta action invented. Requirement 6.8 survives the wire: a core Element has one position, so a multi-position annotation sits at its first occurrence and carries the rest in its payload. An empty map maps to exactly one element, the evolution axis, which is Requirement 1.4's "opens showing its axes and nothing else". A BLANKET INVARIANT TEST - every element has a non-empty id - CAUGHT TWO KINDS I HAD SKIPPED: accelerators and attitude regions were never reconciled, and the mapper was papering over it by asking for an accelerator under the Component kind, which could only ever return empty; an element with no id cannot be selected, moved or reported against, so both would have been inert on the canvas. Both now have real identities, with keys chosen for what they can survive: an accelerator by name AND direction, since an accelerator and a deaccelerator may share a name for opposing forces on one thing; an attitude region has no name at all, so its key is kind plus a corner and moving it loses its identity - acceptable for a backdrop nothing links to, and said plainly in the code rather than left to be discovered. Client stubs: one entry added to the client's generate script, which names each api folder explicitly; wardley-map_pb.ts is gitignored like the other modules' stubs, so it is produced rather than committed. 30 tests across axis and mapper. Verified: 1557 backend tests pass, 383 client tests pass, format gate exits zero.
