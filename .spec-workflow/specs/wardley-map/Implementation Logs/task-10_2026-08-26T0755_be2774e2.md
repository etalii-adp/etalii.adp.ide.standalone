# Implementation Log: Task 10

**Summary:** WardleyDocumentStore and IWardleyDocumentStore: one loaded document per path, shared by every connection viewing it, so two sessions on one map hold one document rather than two that drift (Requirement 10.6). GetOrLoad, Save, Touch, Forget and Reload, with Reload covering the external edit of Requirement 10.7 and never touching the history. A missing file opens as an empty document rather than throwing, per Requirement 2.4, and the sibling is created on the first save. Path keys are case-insensitive because Windows hands the same file back under either casing and two entries would be two documents drifting apart. NOTE THE FACTORY HALF OF THIS TASK ALREADY LANDED IN TASK 3, which needed it to keep the host starting; task 10 is therefore the store alone. SAVES ARE ATOMIC, which is where this deliberately departs from C4DocumentStore. That uses File.WriteAllText, so a reader - the watcher, another client, git - can observe a half-written file. Requirement 3.6 asks for temp-then-move, so this writes a scratch file in the same folder and moves it into place with overwrite. The scratch name reuses AdpFileWriter.TempPrefix ("~adp-") and TempExtension, which HierarchyModel already ignores, so ADP's own temporary never surfaces in the explorer or as a spurious watcher event - and a test asserts the folder contains only the map afterwards. AdpFileWriter itself could NOT be reused: its Create/CreateAll are for new files and move with overwrite:false, and a save is an overwrite. A failed write keeps the edit in memory rather than discarding it, and cleans up its own scratch file; losing an edit because the disk refused would be worse than a save the user can retry. Registered with TryAddSingleton rather than AddSingleton so a test registering its own store keeps it and a second AddWardleyMap call cannot quietly produce two stores. WardleyDocumentChangedEventArgs carries the path alone for now and gains the re-derived map once the parser exists, matching C4DocumentChangedEventArgs's shape. 14 store tests including byte-preservation end to end through the store (CRLF plus a missing final newline), no-temp-file-left-behind, external reload, and case-insensitive sharing. Verified: 1305 tests pass, 86 of them this module's. No new style-diagnostic categories.
