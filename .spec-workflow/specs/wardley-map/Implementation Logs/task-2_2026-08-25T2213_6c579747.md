# Implementation Log: Task 2

**Summary:** Assembled the .owm round-trip corpus: twelve fixtures, ten hand-made edge cases pinning one property each and two realistic maps, plus .gitattributes marking *.owm as -text (verified with git check-attr, and confirmed by git's own CRLF warnings naming only readme.md/certify.mjs/.gitattributes and never a .owm). Fixtures\** is now Content CopyToOutputDirectory=PreserveNewest in the test csproj, mirroring C4's, with certify.mjs excluded; verified the files land in bin/Debug/net10.0/Fixtures. Full suite still green: 1221 tests, 0 failed. THE IMPORTANT PART IS THE CERTIFICATION. Every fixture was parsed by the real OnlineWardleyMaps parser vendored by cli-owm 0.0.2 (MIT, Copyright 2019 Damon Skelhorn) via a committed certify.mjs, which is the counterpart of the C4 corpus being certified by the Structurizr CLI. That found a contradiction with the APPROVED requirements: market and ecosystem are NOT statement keywords, they are decorators. "market Foo [0.6, 0.8]" is a ParseError; the real syntax is "component Foo [0.6, 0.8] (market)", and the parser puts market and ecosystem in the same decorators object as build, buy and outsource - {"ecosystem":false,"market":true,"buy":false,"build":false,"outsource":false}. The DSL's real split is three statement kinds (component, anchor, submap) and five decorators (market, ecosystem, build, buy, outsource); inertia is neither, it is a separate boolean. Requirement 5.1 lists market and ecosystem alongside component/anchor/submap as statement kinds, and Requirement 6.3 lists only three decorators, so both need amending, along with the knock-ons in Requirement 13.2 (toolbox offers Market and Ecosystem as entries), Requirement 15.2 (kind versus decorator in the property grid) and the design's WardleyElementKind. Reported rather than quietly redesigned, per Requirement 12.5. Certification also CONFIRMED Requirement 5.2 with evidence: "component Alpha [0.80, 0.40]" parses to visibility 0.8, maturity 0.4, which is worth having pinned since it is the module's most error-prone single line. Three smaller facts each shape a later task: the parser's line numbers are 0-based while DiagramProblemLineLocation.Number is 1-based; an unknown decorator such as (someDecoratorFromLater) is tolerated silently; and y_axis, style and size all parse without error, so only a genuinely unknown keyword errors. Deliberately NO third-party map content is committed - the Wardley mapping method is CC BY-SA 4.0 and its share-alike terms should not be quietly imposed on this repository, so every file was written for it and then certified, which is the same route C4 took. Caveat recorded in the readme: cli-owm 0.0.2 vendors a parser snapshot and upstream may have moved, so a construct recorded as invalid should be re-certified against a newer parser before anyone concludes otherwise.
