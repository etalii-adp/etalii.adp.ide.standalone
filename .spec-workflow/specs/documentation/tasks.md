# Tasks Document

All implementation happens in **one worktree with a short name** — `.claude/worktrees/docs` — created at the start of task 1 and retired after task 12. Short deliberately: Windows' 260-character MAX_PATH is what turns a long worktree name into `Zero tests ran` (the xUnit v3 apphost trap CLAUDE.md documents), and this spec's tasks run the backend suite repeatedly.

Three phases, each ending in a gate-and-merge task so develop receives working increments. The four gates are the ones `.github/workflows/build.yml` runs, judged by **exit code captured immediately after each command, before any pipe** — a piped `tail` or `grep` overwrites the code that matters, and in this repository a zero-test run exits non-zero and must be seen to.

Spec bookkeeping (marking tasks in progress and complete in this file, logging implementations) happens on develop in the main checkout, per CLAUDE.md.
