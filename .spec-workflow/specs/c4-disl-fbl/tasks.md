# Tasks Document

One Developer owns this specification, per CLAUDE.md's one-owner-per-specification rule, and works it in one worktree (`.claude/worktrees/c4d`, branch `features/c4-disl-fbl`). **The order is the design's two stages and it is load-bearing.** In the first stage (tasks 1 to 12, the design's ten steps) the transcript is frozen before anything changes (task 1), the libraries gain what the definitions call before anything is bundled (tasks 3 and 4), and each hand-written part is replaced in a pull request of its own (tasks 7, 9 and 10), so that a difference in the transcript names one part. `C4Parser` reads every body through the whole first stage, which is what lets a difference be attributed to derivation alone. In the second stage (tasks 13 to 17) the binding is read beside the parser first, then reading switches, then writing, then positions.

**Every task is one pull request into `develop` and leaves the four gates green.** A task whose transcript differs in a way this document does not name is not delivered. The only transcript difference of the first stage is the two empty-canvas labels of task 8.

**Tasks done in etalii-adp/etalii.adp**, through that repository's own pull request: task 2 (the six definitions and their companions), the definition revision of task 8 (the two labels), and the companion and example-binding changes of tasks 12, 13 and 17. Task 5 cannot start before task 2 is merged there.

**The amendments.** This document is written against the recommended option of each amendment the design proposes; a ruling that differs is a small amendment to the tasks named. Amendment 1 (a derived relation's `key` joins the list of Requirement 10.1) touches task 3, which builds it as L6, and task 10, which uses it to merge lifted relationships; under the other option task 3 drops L6 and task 10 keeps the merge in `C4ElementMapper`, named as standing in for a runtime gap. Amendment 2 (the module's binding is committed in the first stage, in the state FBL 0.2 can express) touches task 6, which commits it, and task 13, which widens it; under the other option task 6 is withdrawn and task 13 creates the file and claims 4.1.

**One departure from the design's table of steps.** The design names Requirement 3.6 at step 5. The criterion requires the findings and the payloads to be byte-identical as well, and those are derived at steps 7 and 8, so 3.6 is claimed by task 10, the task after which all five are derived. Tasks 7 and 9 are still held to the transcript for what they derive.
