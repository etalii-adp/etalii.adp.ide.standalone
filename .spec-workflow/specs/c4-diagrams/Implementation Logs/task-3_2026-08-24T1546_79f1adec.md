# Implementation Log: Task 3

**Summary:** Added optional 'body:' and 'view:' headers to the .adp format in DiagramFilePair, resolved against the project root and refused when they escape it. Discovered that SiblingOf drives delete and rename (not only open), so returning a named body from it would have made deleting one C4 view destroy the shared model other views open; ownership is therefore now explicit via the new DiagramBody record (derived sibling = owned and travels with its registration; body: header = never owned), with BodyOf resolving what to open either way. A file with no headers behaves exactly as before. 854 backend tests pass.

### Classes

#### DiagramFilePair.DiagramBody
- **Purpose:** Readonly record struct (Path, ViewKey, IsOwned) describing the body a registration opens and whether it owns it. Ownership is the point: a derived sibling belongs to its one .adp so delete/rename take it along, while a body named by a 'body:' header may be shared by several registrations - C4's model-once-view-many - so one view's deletion must leave the model alone.
- **Location:** src/backend/EtAlii.Adp.Backend/Hierarchy/DiagramFilePair.cs
- **Exported:** No
