# Implementation Log: Task 3.2

**Summary:** Context actions and the toolbox for causal loop diagrams. Every edit gesture from task 3.1 is reachable through the standard IContextActionProvider path, so the ribbon, the right-click menu, a keyboard shortcut and a toolbox drop all dispatch the same command and inherit the same refusals and undo. A gesture that cannot apply to the current selection is discovered unavailable carrying its reason (Requirement 5.4) rather than being silently absent — the one exception being a gesture that is meaningless for the kind selected, such as polarity on a variable, which is not a thing a variable has. One shared selection vocabulary (variable:/link:from|to/loop:/new:x,y) is used by the canvas and both providers. The toolbox is three entries of data from the backend, each naming an action the provider actually offers, so a drop has no implementation of its own. 15 tests, each of the seven load-bearing claims verified by sabotage.
