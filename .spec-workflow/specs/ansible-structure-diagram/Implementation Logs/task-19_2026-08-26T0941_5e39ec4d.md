# Implementation Log: Task 19

**Summary:** AnsibleContextSourceResolver + AnsibleNodeSubscription + a local AnsibleTestDiagramDefinitionCatalog, registered as IContextSourceResolver. Resolves an element_id against the project named by the enclosing hierarchy level, verifies the element is really in that project, checks (never trusts) the client's path, and hands back a DiagramElement-scoped level. Nesting is NotNestable. Decisions: (1) An EDGE is selectable as well as a node, and resolves as its DECLARING side - RelativePath is the file that wrote the directive, and the detail text is "include_tasks: tls.yml" - because Requirement 8.3 says an edge's selection must name the file a reader asking "why is this here" has to open. (2) ContextTarget.ResolvedFullPath is the FOLDER, not the registration file. The mindmap puts its body path there; for this type the analogous thing is the subject, and the property provider (task 20) needs the folder to find the project. (3) A file of another type is rejected with a plain "not an Ansible structure diagram" rather than silence - several resolvers share the element_id member and that is how they coexist; the test constructs a real mindmap .adp beside the ansible one so the path is exercised against an actual other type rather than a hypothetical one. A BUG THE TEST CAUGHT, and the reason ADeletedRole_ClearsTheSelection was worth writing: Track computed its folder as GetDirectoryName(level.Target.ResolvedFullPath), but Resolve had already put the folder there - so it subscribed against the folder ABOVE the project, never matched an event, and the selection would never have cleared when a role was deleted. Silent in production, and only visible because the test waited for a callback that never came (the run took 16s before the fix and 1.9s after, the difference being the timeout). Fixed to use the target path as-is, with a comment naming the test so the next reader knows why it is not GetDirectoryName. Also a local copy of the definition-catalog stub: test projects do not reference one another, and one small internal class beats a project reference existing only to share it. 10 tests. Verified: build 0 errors; module 152/152 twice; Backend 494/494.
