# Implementation Log: Task 18

**Summary:** AnsibleRuleSet.Judge(project) - a pure function, reads no file - implementing all five rules of Requirement 9.2, plus AnsibleRules (the id constants) and AnsibleValidator, now registered in AddAnsibleStructure. Every problem carries a DiagramProblemFileLocation naming the file and line that DECLARED the mistake, never the .adp: a role-missing found via a playbook points at playbooks/deploy.yml, the same rule found via a meta dependency points at roles/web/meta/main.yml. THREE JUDGEMENT CALLS, all about keeping rules from becoming noise. (1) unmatched-hosts is silent when the project has NO inventory at all - "no inventory defines it" presupposes there are inventories to do the defining, and a team keeping theirs outside the folder would otherwise be warned about every play they own. (2) unmatched-hosts ignores all/*/localhost/127.0.0.1/::1, which Ansible resolves without any inventory entry; reporting them would fire on ordinary correct playbooks, which is how a panel teaches people to stop reading it. Both guards have their own tests. (3) AnsibleValidator reads the folder directly rather than through IAnsibleProjectStore: validation is a one-shot question, not a subscription, and routing it through the store would leave a watcher behind on every "Validate all". It reads request.SubjectFolder - this class is the reason task 3 widened the seam - and if that is somehow absent it logs rather than reporting at the user, since a definition/request disagreement is a deployment fault, not a fault in anybody's Ansible. 18 tests: one per rule asserting severity, message and exact location; TheBrokenFixture_FiresEachRuleAndNothingElse (every rule has exactly one subject in that tree, so it proves both "each rule works" and "no rule invented a sixth problem"); EveryProblem_NamesAFileThatExists (a location that points nowhere is worse than none - the panel would offer to reveal a file and then fail); and the two silence tests that carry the most weight, infrastructure/ clean and unconventional/ producing nothing at all. ALSO FIXED, and it was mine: ABurstOfChanges from task 12 asserted a burst costs EXACTLY one re-read. It failed once here and passed three times after - a timing test measuring machine load rather than the store's coalescing, since any stall longer than the settle delay lets the timer fire mid-burst. Rewritten to write the files back to back (as a real multi-file save arrives) and assert the claim that is actually true: materially fewer re-reads than changes, Assert.InRange(count, 1, 5). Five consecutive clean runs after the fix. Verified: build 0 errors; module 142/142 five times; Backend 494/494; Diagram 62/62.
