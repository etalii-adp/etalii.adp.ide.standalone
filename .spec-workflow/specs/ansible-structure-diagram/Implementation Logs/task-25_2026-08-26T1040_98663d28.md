# Implementation Log: Task 25

**Summary:** Two integration flows in EtAlii.Adp.Backend.Tests/Integration Tests/ (where every other flow test lives), plus an AnsibleFixture helper that writes a small but genuine Ansible project - written inline rather than copied from the module's Fixtures/, since test projects do not reference one another and the flows need only enough project to prove core's plumbing. AnsibleStructureFlowTests: four tests over real gRPC against a WebApplicationFactory host - a registered folder opens and delivers its structure, a node's payload carries the project-relative path and measured box the canvas needs, a brand-new role appearing in the folder reaches an ALREADY-OPEN diagram, and opening plus reading changes nothing on disk (the end-to-end form of Requirement 1.1, beyond task 24's component-level proof). AnsibleValidationFlowTests: five tests driven from the DI container rather than gRPC, because the subject is core's validation plumbing and a stream in front would test the stream. THE BUG THIS TASK EXISTED TO FIND, and it was real: AnsibleRuleSet emits locations relative to the DIAGRAM'S FOLDER (roles/nginx/meta/main.yml), but ProjectValidator.LocatedFile resolves a location against the PROJECT ROOT. For a diagram sitting in a subfolder - the ordinary case - every problem was therefore attributed to a path that does not exist, and the panel would have offered to reveal a file and then failed to find it. Completely invisible to all 177 module unit tests, because in those the diagram folder IS the root. Three of the five flow tests failed on it. Fixed in AnsibleValidator with a Rebased() step: the rule set stays in the model's terms and core stays in the project's, and the validator is the one place both paths are known, so that is where they meet. The most valuable test of the five is BreakingAFileAgain_BringsTheProblemBack: clearing a problem could be achieved by task 6's walk-up doing nothing at all, so the test that proves the walk-up genuinely REVALIDATES is the one where a problem has to REAPPEAR from an edit to a file that is not itself a diagram. Verified: build 0 errors; Backend.Tests 503/503 (up from 494, and the run dropped from 20.7s to 7.4s once the three failures stopped burning their waits); module 177/177, Diagram 62, Mindmap 146, C4 400 all unaffected by the rebasing.
