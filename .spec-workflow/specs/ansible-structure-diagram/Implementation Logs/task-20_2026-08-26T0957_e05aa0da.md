# Implementation Log: Task 20

**Summary:** AnsibleContextPropertyProvider, registered as IContextPropertyProvider for ContextScope.DiagramElement - the first provider in the tree whose read-only markings are the whole of its behaviour rather than an exception to it. Groups per Requirement 10.3-10.6: Identity/Runs/Targets for a playbook or play, Identity/Contents/Relationships for a role, Identity/Groups/Variables for an inventory, Declaration for an edge. THE DESIGN DECISION THAT MATTERS: a single private Row(id, label, value, source, group) constructor builds every row and always sets a ReadOnlyReason. That makes Requirement 10.2 true BY CONSTRUCTION rather than by discipline - there is no path through the class that can produce a writable property, because there is no other way to make one. Reasons follow the house shape the mindmap's two read-only rows established, cause then remedy: "Defined in X; edit it in a text editor." Crucially the source is the file the value actually lives in, not the element's own path: a role's dependencies row names roles/nginx/meta/main.yml, because a reader sent to the role folder would open the wrong thing. SetAsync refuses whatever it is given, with a sentence. It is unreachable through the grid (ContextPropertyResolver stops a write to a read-only property before a provider is consulted, verified in that class at lines 60-65 during the task-19 research) and written to refuse anyway. Absent is absent: a role with no meta, templates or handlers contributes no rows for them, so the grid shows what a role HAS rather than a checklist of what it lacks. 21 tests. Two are the headline: a Theory over all seven node kinds asserting every property is non-editable, that its reason is non-BLANK rather than merely non-null (both ContextPropertyDefinition.IsEditable and the client's PropertyRow test string LENGTH, so a whitespace reason would render and behave as editable - the trap I flagged to the wardley-map session earlier), and that the file each reason names actually exists on disk.
