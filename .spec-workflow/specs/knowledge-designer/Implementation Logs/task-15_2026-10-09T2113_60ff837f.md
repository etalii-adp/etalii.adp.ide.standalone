# Implementation Log: Task 15

**Summary:** Views bar, filter and sort items, groups, nested rows and the new row. TableSurface now renders a frame: ViewTabs, ViewBar, then the grid. GESTURES raised (session vocabulary for task 17 onward): views - addView {}; renameView { viewId, values: [name] }; duplicateView { viewId }; deleteView { viewId } (disabled for the last view); moveView { viewId, index }; switching a view is NOT a gesture, it goes out through onView(viewId) to DesignerService.SetTableView. Filter - an item is named by its PLACE, the indexes from the outermost group joined by '/', the outermost group being '': addFilter { columnId, targetId: group path, settings: { comparison } }; addFilterGroup { targetId: parent path }; setFilter { targetId: path, columnId, settings: { comparison }, values }; setFilterMatch { targetId: group path, settings: { match: all|any } }; removeFilter { targetId: path }. Sorts - addSort { columnId, settings: { direction: ascending|descending } }; setSort { columnId, settings: { direction } }; removeSort { columnId }; moveSort { columnId, index }. Grouping - groupBy { columnId or '' }; setHideEmptyGroups { settings: { hide: 'true'|'false' } }; toggleGroup { targetId: group key, settings: { collapsed } }; toggleRow { rowId, settings: { collapsed } }. Visibility - showColumn / hideColumn { columnId }. New row - addRow { settings: { group: key } } with an empty key at the bottom of an ungrouped table (the keyboard's addRow from task 13 carries targetId instead). DEFINITION additions: TableKindDefinition.comparisons (TableComparison { id, label, takesValue? }), sortable (false to exclude), groupable (true to include); isEmpty and isNotEmpty are offered for every kind. WIRE CHANGE: designers.proto TableRow gained is_new_row = 9, with TableRow.IsNewRow in EtAlii.Adp.Designer and isNewRow in the client model - a third kind of line, sent by the backend at the bottom of the table and of every group (its id is the group's key), so every line still has one height and the windowing arithmetic is exact. The session must emit these lines and count them in row_count. Filter nesting: MAXIMUM_FILTER_DEPTH = 3; 'Add a group' is offered at depths 1 and 2 only. A condition's value is the one thing held locally until Enter or blur. Group and nested-row folds are raised and never kept in a component. A read-only table: tabs only switch, the bar's controls are disabled, the new-row line keeps its height and offers nothing. Reused ContextMenu, usePointerGesture and dropIndex (turned on its side for the sort list). Seen to fail: a new row raised without its group's key (2 tests). jsdom lacks CSS.escape, found by the tests and avoided. DEVIATION: one test file, views/views.test.tsx, covers the eight components through the surface. NOT DONE: hiding one group and ordering the groups (Requirement 6.6) have no control yet; the arrow keys do not skip group and new-row lines (the active cell can land on a line with no cell and the focus then stays where it was); the panels open inline under the bar rather than as popovers. These are for the browser pass and the module tasks to settle.
