# Implementation Log: Task 12

**Summary:** The table library: model, surface and stream. src/client/src/table/library is laid out as the canvas library: TableSurface.tsx (entry point), definition/tableDefinition.ts (what a module declares: kinds with icon and label, optional rowHeight and columnWidth), api/tableModel.ts (the library's own shapes, EMPTY_TABLE, applyTableEvent, cellText), api/tableEvents.ts (TableGesture, TableEvents: onWindow, onView, onGesture), rows/windowing.ts (windowOf, spacersOf, sameWindow, indexesOf; DEFAULT_ROW_HEIGHT 33, DEFAULT_MARGIN 10), table.css (host theme tokens only). TableSurface is one scroll container with a sticky header row; it draws only the window's rows between two spacers, draws a line the model does not hold as an aria-busy placeholder of the same height, has roles grid/row/columnheader/gridcell with aria-rowcount and aria-rowindex of the whole view, and calls onWindow once per distinct window. When it cannot measure its height (before layout, under jsdom) it uses fallbackViewportHeight. Rows in the model are the window only: a 'rows' event replaces the map. src/client/src/designers/useTableStream.ts is the one place a table stream is opened: path -> { model, loading, failure, pendingEdits, refusal, setWindow, setView, edit }; it generates the stream id, re-opens after TABLE_RECONNECT_DELAY_MS on a drop with an empty model, re-sends the last window after each baseline, stops on FailedPrecondition/NotFound/Unimplemented with the backend's sentence, and tracks edits by id until their TableEditOutcome arrives. designers/tableWire.ts converts wire messages to library shapes and is the only file that reads generated table messages for the library. workspaceStreams.ts gained table(message) and openTable(streamId, calls, signal) over a shared private open(); ContextConnectionProvider routes the 'table' member and hands out openTableStream.
