# Implementation Log: Task 9

**Summary:** Adding a designer's document with its format. A designer type that declares Formats and registers an IDesignerDocumentTemplate is offered in the tree's Add dialog under its vendor, beside the diagram types, as a heading with one selectable choice per format (option id '{origin}@{extension}'). Committing creates the body (the template's content for that format) and the registration through the existing CreateDiagramFileCommand, so both appear or neither and one undo removes both. DeleteEntryCommandHandler now knows designers: deleting the registration removes the body, deleting the body removes the registration. THREE DEVIATIONS from the task text, each deliberate: (1) no AddDesignerContextActionProvider: ContextActionResolver gives an action to the first provider reporting its id, so a second provider reporting hierarchy.add would show a second Add and never commit; DesignerAddOptions contributes to AddDiagramContextActionProvider instead (optional ctor parameter). (2) The registration ALWAYS carries 'body: name.ext' (CreateDiagramFileCommand.NamesBody), not only 'when the names differ': a body has one of several extensions and DesignerFileRouter's fallback takes the first format that exists, so a cities.yaml already there was taken for the body of a table created as cities.json; a test pins it. DesignerFileRouter resolves a bare body: file name beside the registration without a project root. (3) No DesignerDocumentTemplates-with-TemplateWriter in the core: the Designer core references only EtAlii.Adp, so the module supplies content through IDesignerDocumentTemplate and calls TemplateWriter itself (task 17 onward must implement it with ShortGuid.NewShortGuid for newid). KnowledgeTemplates.Tests proves the three templates of knowledge.fbl read through their own binding with no finding as one title property, one view, no rows, and do not read as a table through another format's binding. Seen to fail: template of the wrong format (json and xml cases), registration with a layout: block, registration without body: line, delete that ignores designers (undo leaves the body). NOT DONE here: renaming a designer document does not rename its body or rewrite the body: line; the dialog title still reads 'Add diagram'; error texts of the create command still say 'diagram'.
