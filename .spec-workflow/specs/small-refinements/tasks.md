# Tasks Document

Three refinements, grouped the way the design keeps them: independent of one another, each finishing work already begun elsewhere. One worktree for the whole spec, `.claude/worktrees/smref` — short, because Windows' 260-character `MAX_PATH` makes a long worktree name silently break the xUnit v3 apphost, and the symptom is `Zero tests ran` rather than a build failure. Each group ends with a gate-and-merge task that runs the four gates and judges them by exit code before that group's commits reach `develop`; a group is not done until its gate is.

Standing notes an implementer should not have to rediscover:

- **Line endings.** CRLF in the working tree, LF in the index, per CLAUDE.md. Anything that generates a file (`node`, redirected shell output) writes LF and earns a `LF will be replaced by CRLF` warning; that warning is the signal, not a fault to silence.
- **Examples exist twice.** Every module example under `src/diagrams/*/examples/` or `src/editors/*/examples/` has a replica under `src/examples/`, and structure.md says the two must never drift. A replica changes in the same commit as its original, byte-identically for the families in scope here.
- **The main checkout is shared.** `.spec-workflow/` bookkeeping is committed on `develop` in `C:\git\EtAlii.Adp` with an explicit pathspec no broader than the change; code work happens in the worktree. Never `git add -A` or `git add .` in either.
- **An agent commits under its own name** with the model trailer, per tech.md; never the repository owner's.
- **Bugs found leave a guard behind** per CLAUDE.md: a test where one can express it, a `tests.md` entry naming this spec where only a running app can.
