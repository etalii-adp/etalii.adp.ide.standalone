# Implementation Log: Task 18

**Summary:** Whole-spec implementation (tasks 1-18) plus the manual F5 verification pass. Backend: a scope-based context-action mechanism - context.proto's scope-agnostic vocabulary, five new RPCs on HierarchyService reusing WatchHierarchy's already-open per-connection stream for backend-initiated prompts, an injected IContextActionProvider seam, and one core provider giving Rename (F2) and Delete (Delete). ### API Endpoints

#### gRPC unary etalii.adp.HierarchyService/DiscoverActions
- **Purpose:** Returns the actions currently available for a source within a scope, each with id, label, icon, keyboard shortcut and availability. Reports nothing for a target that no longer exists or that this connection does not know.
- **Location:** src/backend/EtAlii.Adp.Backend/Hierarchy/HierarchyServiceImpl.Context.cs:20
- **Request Format:** DiscoverActionsRequest { project_id, watch_id, scope, source }
- **Response Format:** DiscoverActionsResponse { repeated ContextActionGroup groups }

#### gRPC unary etalii.adp.HierarchyService/ExecuteAction
- **Purpose:** Starts an action, triggered either by action id (context menu) or by a ContextShortcut (keypress). Any dialog the action needs is pushed back as a ContextPrompt on the caller's own WatchHierarchy stream.
- **Location:** src/backend/EtAlii.Adp.Backend/Hierarchy/HierarchyServiceImpl.Context.cs:35
- **Request Format:** ExecuteActionRequest { project_id, watch_id, scope, source, interaction_id, oneof trigger { action_id | shortcut } }
- **Response Format:** ExecuteActionResponse { accepted, error }

#### gRPC unary etalii.adp.HierarchyService/ProposeInput
- **Purpose:** Judges a value the user proposed for an in-flight action; the verdict returns on this call's own response and echoes the request's revision so a stale reply is recognisable.
- **Location:** src/backend/EtAlii.Adp.Backend/Hierarchy/HierarchyServiceImpl.Context.cs:103
- **Request Format:** ProposeInputRequest { interaction_id, revision, value }
- **Response Format:** ProposeInputResponse { revision, valid, reason }

#### gRPC unary etalii.adp.HierarchyService/SubmitInteraction
- **Purpose:** Performs the action after the user confirmed it, re-validating first. Completing removes the interaction so a duplicate submit is a clean no-op; a failure leaves it in flight so the dialog can stay open with the user's input.
- **Location:** src/backend/EtAlii.Adp.Backend/Hierarchy/HierarchyServiceImpl.Context.cs:120
- **Request Format:** SubmitInteractionRequest { interaction_id, value }
- **Response Format:** SubmitInteractionResponse { completed, error }

#### gRPC unary etalii.adp.HierarchyService/CancelInteraction
- **Purpose:** Abandons an in-flight interaction when the user dismisses its dialog.
- **Location:** src/backend/EtAlii.Adp.Backend/Hierarchy/HierarchyServiceImpl.Context.cs:145
- **Request Format:** CancelInteractionRequest { interaction_id }
- **Response Format:** CancelInteractionResponse {}

#### gRPC server stream (widened) etalii.adp.HierarchyService/WatchHierarchy

### Classes

#### IContextActionProvider
- **Purpose:** The extensibility seam: contributes the actions available for a target within one scope and performs them (DiscoverAsync/ExecuteAsync/ValidateAsync/CommitAsync). A later diagram-type module adds actions - with their own keyboard shortcuts - by registering another implementation, with no core code change. Providers never resolve a location themselves; ContextTarget.ResolvedFullPath arrives already containment-checked.
- **Location:** src/backend/EtAlii.Adp.Backend/Context/IContextActionProvider.cs
- **Exported:** No

#### ContextActionResolver
- **Purpose:** Fans out to every provider whose Scope matches, concatenating their groups in registration order, and resolves an action id or a shortcut to its owning provider. Contains no action id or shortcut of its own; a shortcut bound to an unavailable action resolves to nothing.
- **Location:** src/backend/EtAlii.Adp.Backend/Context/ContextActionResolver.cs
- **Exported:** No

#### ContextInteractionStore
- **Purpose:** Per-watch_id prompt channel and in-flight interaction state, structurally mirroring HierarchyModelStore. TryPush only ever writes to that exact connection's own writer - never broadcasts - and Complete removes the interaction so a duplicate submit is idempotent.
- **Location:** src/backend/EtAlii.Adp.Backend/Context/ContextInteractionStore.cs
- **Exported:** No

#### HierarchyContextActionProvider
- **Purpose:** The single core provider for ContextScope.Hierarchy: reports Rename (mdi-pencil-outline, F2) and Delete (mdi-trash-can-outline, Delete) always - unavailable-with-reason rather than omitted - and nothing at all for a target that no longer exists. One ValidateAsync drives both the live dialog verdict and the pre-commit re-check, so the two cannot drift. Rename is a single File.Move/Directory.Move; folder delete is one recursive Directory.Delete. Action ids are the public constants RenameActionId and DeleteActionId.
- **Location:** src/backend/EtAlii.Adp.Backend/Hierarchy/HierarchyContextActionProvider.cs
- **Exported:** No
