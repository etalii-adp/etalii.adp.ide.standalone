# Implementation Log: Task 1

**Summary:** Addendum to task 1: five more azure-pipeline floors, found by counting collections rather than sites. Task 1 named seven sites; six were floored in the first pass (merged c4aea9dc). Re-reading those six by collection found five of them walking a SECOND collection which carries the assertions and which the first floor says nothing about — a guard proving the corpus was found proves nothing about whether anything came out of it. Two are the sharper kind: PipelineWriter's loop takes a `continue` when a fixture has no editable stage, so every iteration can skip and the walk completes green having renamed nothing while still reading fourteen files; the action provider's inner loop walks the actions offered on each element, so a provider offering none would visit nine ids, execute nothing and pass. Bounds are measured, not guessed: the corpus maps 64 elements, yields 25 stages, eight of fourteen fixtures offer an editable stage, and the nine element ids carry 38 actions. A per-fixture floor on stages would fail on correct code — six of the fourteen fixtures declare no stage line at all — so that floor is on the corpus total. Both halves of the control run were performed: with the five collections emptied and the floors in place, exactly those five tests fail, each naming its own guard and each reporting 0, with the other 443 green; with the same collections emptied and the five floors REMOVED, the suite passes at 448, which is what proves the floors were needed rather than merely present. The seventh named site (PipelineContextActionProvider.Tests.cs:496) still gets no floor: it walks a nine-element array declared in the test, which the design's Deviations exclude by name — the scan classified it shape B, "a collection the code under test produced", and it is not one. Separately verified and reported: xUnit floors empty TheoryData itself ("No data found for ..."), so no [MemberData]-driven theory needs a floor — this exempts PipelineDocument.Tests.cs:20, PipelineLayout.Tests.cs:91 and PipelineParser.Tests.cs:23, whose relative "Fixtures" path is a portability wart rather than a vacuity hole. Still unowned in this group: PipelineLayout.Tests.cs:147 walks graph.Edges.Where(edge => !edge.IsBroken), a filtered collection that can empty, outside task 1's named list. Note for the record: task 11's completion commit 8bde83f2 claims 24 collections needed a floor and all 24 carry one; these five contradict that count, with the control run as evidence.
