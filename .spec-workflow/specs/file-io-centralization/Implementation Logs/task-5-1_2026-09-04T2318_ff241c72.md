# Implementation Log: Task 5.1

**Summary:** Tasks 5.1, 5.2 and 5.3 together, because they turned out to share one blocker.

**The finding task 5.1 invited.** It said "if `AdpFileWriter` cannot express it, that is a finding to report rather than an encoding to change". The encoding was expressible; the *overwrite* was not. `AdpFileWriter`'s entire surface was `Create`/`CreateAll`, both moving with `overwrite: false`, and all four sites are saves — which are overwrites. `WardleyDocumentStore.cs:151` already said so in a comment: *"It cannot use `AdpFileWriter` itself: that creates files and refuses to overwrite, and a save is an overwrite."*

**Why one method rather than four justifications.** All four sites were the same eight lines — a `~adp-` scratch file in the destination folder, `File.WriteAllText`, `File.Move(overwrite: true)`. That is `AdpFileWriter`'s own algorithm differing in one boolean. Requirement 2.2 permits justifying instead of converting, but four permanent allow-list entries for one shared cause is exactly how a permanent list stops meaning anything.

**`AdpFileWriter.Save(path, content)` imposes no error policy, deliberately.** It throws; each caller keeps what it had — mindmap propagates, the Wardley store and the two sidecars catch and keep the edit in memory. **Centralizing the algorithm while quietly centralizing the error handling would have changed three modules' behaviour under a commit claiming to change none** — the same trap as the view-delta extraction, where the proof was what stayed untouched. What each caller *stops* doing is removing its own scratch file, since `Save` cleans up before letting the failure out; that retired `C4LayoutSidecar.TryDelete`, which had exactly one caller.

**Encoding preserved exactly**: UTF-8 without a BOM — what mindmap asked for explicitly and what `File.WriteAllText` gives the other three by default. Pinned by a test, because a BOM would change the bytes of every document these stores save and the round-trip corpora compare bytes.

**Verification.** Seven tests on `Save`, two sabotage-verified: `overwrite: false` fails `Save_ReplacesWhatIsThere_WhichIsTheWholeDifferenceFromCreate`; emitting a BOM fails `Save_WritesWithoutAByteOrderMark`. **One of the seven was wrong when written** — it expected `IOException` where moving onto a folder raises `UnauthorizedAccessException`. It now asserts the pair every caller actually catches, which is a better statement of the contract than my guess was, and explains why all four catch clauses name both types.

**The guard was watched firing before any line was deleted**, per Agent 7's advice: `NoTrackedEntryOutlivesItsFix` named all four files with their owning tasks. The four tracked lines are gone in the same commit as the conversions, the `HandRolledPublish` category is empty, and its heading went with its last entry as the read categories did before it.

**Correction carried in from elsewhere, not fixed here.** The tracked entry `("Hierarchy/RegistrationLayout.cs", RawRead, "backend-consistency AC2")` points at the read at `:293`, which sits inside a `catch` swallowing `IOException` and returning `null` — it cannot surface anything. The observed lock is the **unguarded `File.WriteAllText` at `:178`**, reached from `RemovePosition` (`:110`) via `WriteBlock`, surfacing at `SetRegistrationLayoutCommandHandler.cs:76` as *"Could not remove the position: … used by another process"*. Out of scope for group 5 and left alone; Agent 7 has taken it as group 6, since the guard has no rule at all for an unguarded write to a user document.

### Functions

#### AdpFileWriter.Save
- **Purpose:** The overwriting half of the central atomic writer: publishes content over whatever is at a path via a scratch file in the same folder and a File.Move(overwrite: true), so a reader sees the previous version or the new one and never a half-written file. Removes its scratch file if the write or move fails, then rethrows the original exception. Imposes no error policy - callers keep theirs. Added because Create/CreateAll refuse to overwrite and every document save is an overwrite.
