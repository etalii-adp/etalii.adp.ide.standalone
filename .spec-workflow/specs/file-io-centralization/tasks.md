# Tasks Document

**The guard comes first, and that is the whole sequencing decision.** This spec's headline defect — two header helpers reading registrations at default sharing — was fixed before implementation started (design F1). What remains is worth less as a fix list than as a guarantee that the next copy cannot be written unnoticed, and a guard sequenced last is a guard that gets cut once the interesting work is done. Task 1.1 therefore lands the guard on day one, green, with the known outstanding sites listed as tracked exceptions; **every later conversion deletes one line from that allow-list**, so the guard tightens as the work lands instead of arriving after it.

**Which test this spec applies to a merge: sameness, not resemblance.** `LineRange` is declared four times, identically, at line 13 of four files — one value type, four consumers, no argument required. That is *sameness*. Contrast the ruling made twice on the view-delta diff bodies, where three modules had resembling diff bodies and extraction was refused because one emits Remove-then-Add where another emits Add-then-Remove: that is *resemblance*, and resemblance is not a merge candidate. Where this document proposes a merge it carries the measurement that makes it sameness; where it declines one (intra-line offset splice) the design says why.

**Independently landable, and therefore one worktree per agent.** Tasks 3.1, 3.2 and 3.3 touch three different modules and share no file. Tasks 4.4 and 4.5 touch two different modules once 4.1-4.3 have landed. Under CLAUDE.md's amended worktree rule these may be taken by different agents in their own short-named worktrees, in parallel. Everything else is sequential: **2.1 must land before group 4**, because `LineDocument` depends on the moved `LineRange`.

**Working in the shared main checkout.** Commit with an explicit pathspec — `git commit -F msg -- <paths>` — and read `git status` for files you did not touch before merging. Both hazards are written out in CLAUDE.md under "Committing and merging in the shared main checkout" (commit `db3bc0c0`); a bare `git commit` has swept another agent's staged files into an unrelated commit three times.

**Gate discipline, every gate task.** Set `MSBUILDDISABLENODEREUSE=1` and `DOTNET_CLI_USE_MSBUILD_SERVER=0`. Capture each exit code before any pipe — redirect to a log, take the code on the next line, judge the variable, read the log only to explain a failure. A zero-test run exits 5 having printed no failures at all.
