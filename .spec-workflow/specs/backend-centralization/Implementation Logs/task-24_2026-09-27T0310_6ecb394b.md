## Behaviour changes the PRs declared, checked against the code

- **R2.4 authorises sparql's one behaviour change (#51, task 7).** Before, a reload that could not read the query replaced a good query with an error entry and told every session. After, the last good query is kept and nobody is told. A query becomes the "does not exist" entry only on the watcher's `BodyDeleted` (R2.5). This holds because keep-last-good on reload applies to every store, and a module's declared state governs only the first open (the user's chat ruling, 2026-09-25).
  - **No existing sparql test pinned the old behaviour, so none changed.** The new `SparqlDocumentReloader.Tests.cs` was seen to fail against the old reload.
  - There is a second, smaller change: a refused read is now retried on first open too, so a held file takes about 200 ms longer to open as unavailable.
- **azure-pipeline's line document (#65, R1.2 and R1.4).**
  - A file with equal LF and CRLF counts now gives an inserted line CRLF (it used to give LF). The rule is `LineDocument.cs`, *"a tie goes to CRLF rather than to LF"*.
  - A range whose end precedes its start is now refused, where it used to be spliced as an insertion. The refusal is `LineDocument.cs`, *"Line {range.End} cannot precede line {range.Start}."*
  - **`IsComment` was the third drift, and #65 itself says no criterion names it**: azure-pipeline's `IsComment` trimmed spaces only, and core's `Line.IsComment` trims all whitespace. **Under R8.1 that is a change without a criterion. It is recorded here, and it is inert in production today.** After #69, azure-pipeline's production code never reads `Line.IsComment` (`grep` finds it only in `PipelineParser.Tests.cs` and in causal-loop's parser), because `YamlNodeRange` judges trailing comments by its own space-only rule.
- **The YAML node range (#69, R7.1 and R7.2).** It adopts azure-pipeline's space-only rule over databricks', dependency-graph's and timeline's all-whitespace rule, under design S7.
  - The measurement: 695 generated inputs, 127 disagreements. In every one the disputed line was a block scalar's last content line, which the three's rule cut out of its element.
  - This changes behaviour in databricks, dependency-graph and timeline for that input, and **R7.2 names it**.
- **ansible-structure's `Targets` edge ids (#59).** They are now unique per inventory: `edge:<source>|Targets|<pattern>|<inventory id>`.
  - This is a fix beyond R4.2, made because `DiagramDiff` refuses duplicate ids (a decision card in the project thread). No criterion here names it, so it is recorded as a ruled defect fix.
  - #59 left one case unfixed: a role listed twice in one play, or a task file included twice by one role, would still repeat an id. No fixture has that case.
- **Removals before additions (R4.5)** in the five converted modules (#57, #59). **This is not yet true of every module**, and that is a coverage gap: see task 25's table.
- **causal-loop's catch-all removed (R5.2, #57).** `CausalLoopSession.cs` now has no `catch` at all, and `ADefectWhileReRenderingAChange_ReachesTheCaller` pins that.
  - **#57 says design.md does not state what reaches the caller. That is wrong: design S5 has stated it since `4305d8b5` (2026-09-22).**
  - **But what S5 states is inaccurate for the common path.** It names *"`DiagramDocumentReloadBridge`'s per-document `try` on the watcher-error path"*. That `try` guards only the path taken after a watcher `Error`. An ordinary change event reaches the store through `RootFolderWatcher.Dispatch`, whose own `catch` logs the exception, which is what #57 describes.
  - This is reported rather than edited: the design is approved.
- **Gaps found and deliberately left:**
  - Swapping x and y when parsing a free-canvas `new:x,y` placement goes unnoticed in causal-loop's and rdf's suites (#63).
  - All four old YAML range copies alike cut a block scalar's last content line if it starts with `#` after its spaces. #69 left this as is, because R8 allows no change a criterion does not name.
