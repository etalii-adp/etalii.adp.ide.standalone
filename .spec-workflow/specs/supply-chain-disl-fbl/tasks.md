# Tasks Document

One Developer owns this specification, per CLAUDE.md's one-owner-per-specification rule, and works it in one worktree (`.claude/worktrees/supply`, branch `features/supply-chain-disl-fbl`). **The order is the design's eleven steps and it is load-bearing**: the transcript is frozen before anything changes (task 1), what derives is switched while the reader and the writer stay (tasks 5 to 7), and only then the reader (task 10) and after it the writer (task 11), so that a difference in the transcript can be attributed to one change. The design's step 3 is two tasks here, the library work (task 3) and the bundling (task 4), because each is reviewable alone; every other step is one task.

**Every task is one pull request into `develop` and leaves the four gates green.** A task whose transcript differs in a way this document does not name is not delivered. Through task 9 the transcript is reproduced byte for byte; at task 10 one sentence may differ; at task 11 only edit hunks may differ.

**Task 2 is done in etalii-adp/etalii.adp**, through that repository's own pull request. Tasks 3 and 4 cannot start before it is merged there. Tasks 9 and 12 each carry a second pull request there, for the companion document, and task 12 a third part, the binding offered as an example.

**Tasks 10, 11 and 12 wait, and nobody starts them early.** They wait for one thing: FBL's construct for a YAML scalar read as written (gap 1, findings B1 and B2), which is a language change in etalii-adp/etalii.adp, reported by `timeline-disl-fbl` and ruled on by that specification's Q3. Until that construct is in the FBL specification the binding of the requirements' appendix is not valid FBL and is not committed. Task 10 starts when the construct has landed there, task 11 when task 10 is on `develop`, task 12 when task 11 is. No workaround is built in their place (Q3, default). The specification therefore stays open after task 9, with tasks 1 to 9 delivered and its owner still its owner.

**Task 3 holds shared library work.** `reachable` and `predecessors` (L1) are also needed by `azure-devops-pipeline-disl-fbl`, `databricks-disl-fbl`, `functional-decomposition-graph-disl-fbl` and `rdf-disl-fbl`, and `formatNumber` (L2) by `sankey-disl-fbl`. Each is delivered once, by whichever specification reaches its library step first. The Developer looks on `develop` before starting task 3: what is present is used and not added again, and what this task adds is announced to the Scrum master so the others find it.

**This document is written against the recommended option of each amendment the design proposes; a ruling that differs is a small amendment to the tasks named.** Amendment 1 (removing a group clears the `group` key by the reference's deletion policy, not by a hook) touches tasks 2 and 7, and task 3 if a hook is ruled instead. Amendment 2 (finding A7 amended: a host binds the selection already, only the two graph functions are missing) touches tasks 3 and 9. Amendment 3 (a dangling flow reported by rules over the written ends, not by `std.references`) touches tasks 1, 2, 6 and 10.
