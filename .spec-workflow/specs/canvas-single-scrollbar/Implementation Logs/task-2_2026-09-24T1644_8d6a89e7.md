# Implementation Log: Task 2

**Summary:** The rule that makes task 1 pass: one declaration, .library-canvas-surface { display: block }. WHY display:block RATHER THAN vertical-align:top (R1.3): both remove the same four pixels and a measurement cannot tell them apart, but only this one stops the surface being an inline box at all — a surface left inline with its alignment corrected is one line-height change away from the same defect, and the criterion is about the box rather than the pixels. WHY ITS OWN RULE RATHER THAN A LINE ON .canvas-drawing (R2.1): that class carries SIZING and is worn by every hand-written canvas; this is the library surface's own box. Amending it would be behaviourally identical today because nothing else wears it, and it would put a library-specific fix on a shared class where the next reader cannot tell which canvas it was for. THE REASON IS IN THE COMMENT (R2.3) and it is also what stops the rule reading as redundant beside the sizing rule above it: that one says how big the surface is, this one says what KIND OF BOX it is. .library-canvas in the same file records the same failure reaching it once before, on the wrapper rather than the surface.
