So at this image's own viewport the defect produces NO pane scroll at all, and no capture taken there can be showing a scrollbar it caused. The vertical affordance visible in the image is the diagram's own. THE INSTRUMENT IS NAMED because the two available ones are not equivalent evidence: the in-app browser at 1600x900 with a live perturbation, NOT a capture.mjs recapture compared against the committed file. A pixel comparison answers whether two images differ, which is a weaker question than whether the defect can appear at that viewport at all — and it would have needed puppeteer-core, which is not in the tree and was NOT added. THE EYE COULD NOT HAVE SETTLED IT: the image is 1600px wide and the defect is four pixels, so a second bar beside the first would be about the width of the rendering itself. BOTH OUTCOMES WERE ACCEPTABLE AND ONLY AN UNRECORDED ONE WAS NOT — retaking would not have been wrong, it would have been a ritual that taught nobody anything.
