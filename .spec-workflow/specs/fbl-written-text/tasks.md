# Tasks Document

One Developer owns this specification, per CLAUDE.md's one-owner-per-specification rule, and works it in one worktree (`.claude/worktrees/fwt`, branch `features/fbl-written-text`). **The order is the design's seven steps and it is load-bearing**: the two steps that cannot change any reading come first (tasks 1 and 2), the one change that reaches every caller of a `yaml` or `json` binding comes alone (task 3, ids and references), and the two changes that reach only a caller that hands over attribute types come after it, each alone (tasks 4 and 5), so that a difference in a tool that already reads through the library can be attributed to one cause.

**Every task is one pull request into `develop` and leaves the four gates green.** This is library work: no module is converted and no module is edited. A task after which a transcript or a fixture test of a tool that reads through the library differs is not delivered, and the difference goes to the Scrum master as a selection before anything is regenerated (Requirement 6.2).

**No task is done in etalii-adp/etalii.adp.** Task 6 copies from a checkout of that repository at commit `5c62e79`, which is already merged there, and task 7 lists what FBL 0.5 leaves unclear as candidate changes for that repository without making them.

**Which tasks wait, and on what.**

- **This document waits on the requirements card.** Requirement 8 was added to the requirements on 2026-10-12, as the design proposed and as the design's card, approved in the dashboard on 2026-10-12, named. An approval covers only its own file, so the amended requirements have a card of their own, and no task here starts before it is approved. A verdict that changes Requirement 8 is an amendment of task 7 and of nothing else: tasks 1 to 6 do not depend on it.
- **Task 1 waits on nothing else.**
- **Each of tasks 2 to 7 waits on the task before it being merged on `develop`.** Tasks 3, 4 and 5 in particular are never combined: task 3 is the only one that can move the transcript of the hype cycle graph or of the agent activity diagram, and tasks 4 and 5 are the only ones that can move an attribute of the Knowledge designer.
- **Seven specifications wait on this one**, and none of their tasks starts on a workaround meanwhile. Task 7 says for each which of its tasks is unblocked.

**Two requirements bind more than the task that claims them.** Requirement 6.1 (every transcript and fixture test reproduced unchanged) and Requirement 7.2 (four gates, judged by captured exit codes) hold for every task. Each is claimed once, by the task after which it can be shown in full: 6.1 by task 5, the last task that changes a reading, and 7.2 by task 7, which reads the captured exit codes of all seven pull requests back. Requirement 2.2 has two sentences: task 4 claims it and delivers the first (a slot reads its written text), and task 5 delivers the second (a typed slot is converted to its attribute's type) and says so.
