# Implementation Log: Task 5

**Summary:** The guard that stops a sixth private scrollbar. One vitest file walks every `src/diagrams/*/client/**` source and fails, naming the file, when a module builds bars of its own instead of importing `@client/canvas/scroll`. Components may name the bars as much as they like provided they import the shared ones; stylesheets may only place them, through the compound `.<module>-scrollbars.canvas-scrollbar-<axis>` selector the component's `className` prop exists for. Walk-and-collect shape, matching DependencyInventoryTests / DocumentationLinksTests / WorkspaceLockTests: every offender reported, not just the first.

Both real findings came from sabotage, not from watching it pass.

(1) The component check first read "mentions a scrollbar without importing the shared module" — which every wired canvas satisfies merely by importing `scrollExtentOf` for its axes. Replacing C4Canvas's `CanvasScrollbars` import with a hand-rolled `<div className="canvas-scrollbar-thumb" />` therefore sailed straight through a green run. The shared component's internal class names (`canvas-scrollbar-thumb`, `scroll-thumb`, `scroll-track`) are now tested separately from the import, and that exact case is pinned as a unit case on `offenceIn` so it cannot regress.

(2) The canary — "the walk still sees more than twenty files" — failed on its first run and earned its place immediately. `src/client/src/diagrams` sits between this test file and the real source root, so a walk anchored on the folder name alone stops there, finds no module clients, and reports a clean tree for ever. The root is now recognised by `diagrams/` and the tree's single `.editorconfig` together, with the trap written down beside it.

Its limit is stated in the file rather than glossed: it reads text, so it catches the copy — which is how this actually happens, somebody starting from a canvas that already has bars — and not a from-scratch reinvention under an unrelated name.

Discovered in passing and needing to reach task 6: **sparql now has a client folder with the shared scrollbars already wired** (`SparqlCanvas.tsx` imports both `CanvasScrollbars` and `scrollGeometry`, and passes `className="sparql-scrollbars"`). The design's Deviations note records sparql as having no client folder at all, which was true when it was written; the sparql-diagram spec has since landed one. Task 6's readme entry must therefore record sparql as done, not as pending and not as exempt.
