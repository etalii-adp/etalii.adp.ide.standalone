**The readme also distinguishes the two shapes of caller**, because that is what decides how a twelfth canvas wires itself. A canvas driving an SVG `viewBox` needs no measurement: its view's span in content units *is* `w` and `h`, so the conversion is four numbers with no ref and no fallback for the frame before layout settles. A canvas driving pixels-per-unit must measure its own element and tolerate a null rect. Worth writing down because the same `viewBox` model is the awkward one for pointer-delta gestures — a model can be inconvenient for drags and convenient for reporting a viewport, and conflating those two findings would be easy.

**`tests.md` gains the one thing no unit test can hold.** jsdom gives every element a zero-sized `getBoundingClientRect()`, so a track has no length and a thumb no pixels; the per-canvas tests reason entirely in the fractions the geometry returns. Whether those fractions land as a bar a person can see and grab is a question only a browser answers. The check covers one canvas of each shape (c4 and timeline) and includes the fitted-view case, where a thumb filling its track and refusing to move is correct rather than stuck.
