# Implementation Log: Task 3

**Summary:** Pan and connect preview routed through the gesture-frame scheduler (Requirements 1.1, 1.5, 2.1-2.3). Pan: per applied frame a LiveWrite pair (panWrites in DiagramCanvas.tsx) writes the svg's viewBox attribute and the scrollbar thumb style positions (left/top via thumbOf, queried from the canvas root at gesture start) directly to the DOM, capturing what React last rendered on first application and restoring it on revert; the view becomes state ONCE at release, so view-changed reaches the modules once per pan rather than once per pointer frame - all fifteen modules setViewport on it, which is precisely what made pan O(elements) through their own re-render. Connect: the ConnectPreview flows through a second GestureValue cell; a new ConnectPreviewLayer component is the gesture's own subscriber, re-rendering per frame to draw the routed path, and each LibraryElement subscribes with a PRIMITIVE snapshot ("valid"/"invalid"/undefined) so the highlight still renders under the pointer while only elements whose answer changed re-render; the connect state, setConnect and connectRef are retired, and onDragEnd's anchor case reads the cell before committing. Per-move elementAt hit-testing kept deliberately (computation, not rendering). The last per-move getBoundingClientRect calls are gone - every gesture reads its rect once at start (Requirement 1.3 complete).
