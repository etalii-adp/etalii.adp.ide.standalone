# Implementation Log: Task 1

**Summary:** Defined the diagram-definition schema and its validators as plain data under src/client/src/canvas/library/definition/. diagramDefinition.ts holds DiagramDefinition, ElementTypeDefinition (thirteen BuiltInShape values - the seven existing components plus rounded-rectangle/diamond/hexagon/pill/parallelogram/cylinder - or CustomShapeRef with render + edgePoint + anchors), RelationTypeDefinition (seven BuiltInRoute values - straight/polyline/orthogonal/arc/quadratic-bezier/cubic-bezier/spline - or CustomRouteRef with a path builder; endpoints with source/target EndpointConstraint, allowSelf, Cardinality; adjustable), AnchorSet (edge | compass | side-fractions | explicit points), LabelRule/RouteLabelRule, ElementStyle/ConnectionStyle with theme-token colour names and MarkerKind (five built-ins + CustomMarkerRef), ToolboxDefinition (derive-by-default with suppress/add), LayoutDefinition (modes list, dragUnderAutomaticLayout, treeDirection) and DraggingPolicy. BUILT_IN_SHAPES and BUILT_IN_ROUTES exported as enumerable constants for the later guards. No React and no serialized closures; the two custom refs deliberately carry client-side functions and the doc comment says why. validateDiagramDefinition returns every complaint (zero layout modes; endpoint naming an undeclared element type; custom shape without render/edgePoint; custom route without path); assertValidDiagramDefinition throws with the list. 9 tests: each validator rejects its bad input and accepts a good one, the four existing connector families map onto the built-in routes (straight; cubic-bezier for bezier+fixed-bezier; cubic-bezier+adjustable for interactive; arc), with named-member canaries. Sabotage (validator returning [] unconditionally) reddened exactly the five rejection-side tests; reverted, 9/9 green, typecheck 0. One test bug found and fixed during the run: replacing elementTypes in the custom-shape acceptance test dropped a type the relation still targeted, tripping the wrong validator. Worktree commit 113ead15 on claude/dlib.
