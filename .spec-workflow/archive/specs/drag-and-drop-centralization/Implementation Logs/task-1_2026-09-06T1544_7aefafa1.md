**Summary:** The gesture-frame scheduler (src/client/src/canvas/library/gestureFrame.ts): the surface rect cached at gesture start (Requirement 1.3), a requestAnimationFrame coalescer applying the latest value once per displayed frame (Requirement 1.2), live-write handles that each know how to undo themselves, and commit/revert/cancel (Requirement 2.3). (2) The user chose (AskUserQuestion, 2026-09-06) the scoped re-render resolution for tasks 2-3: per-frame values will publish through a live-write handle to a store only the gesture's own participants subscribe to, because mindmap (drop ring/edge preview computed in the shape render from the dragged element's shifted position), wardley (mid-drag clamp visible on the circle's cx) and c4 (inner .c4-node transform and c4-node-dragging state class) all render mid-drag feedback from the dragged element's live position, and the design's pure-transform write would freeze them - failing their existing tests, which Requirement 2.1 forbids changing. Non-gesture elements still render zero times per frame (Requirement 1.1), which task 4's guard asserts.
