# Implementation Log: Task 9

**Summary:** PARTIAL - the sidecar's storage half only. WardleyIdentities gives PathFor, Read, Write and Remove for a <name>.identities.json beside the .owm, plus the WardleyIdentityEntry(Id, Kind, Key) record. Follows C4LayoutSidecar's precedent and, more importantly, its posture: an optimisation and never a dependency (Requirement 4.5). Nothing throws for a bad file - a missing, unparseable, or wrong-shaped-JSON sidecar yields no entries and the identities get re-derived from the document, because a map that will not open because its bookkeeping file is corrupt would be a poor trade. A half-written entry (empty id, kind or key) is discarded without costing the entries around it, since an identity with no key to match by cannot do the one job it exists for. Writes are atomic like the document store's, reusing AdpFileWriter.TempPrefix/TempExtension so the scratch file stays invisible to the explorer and the watcher; a test asserts the folder holds only the sidecar afterwards. An empty entry list removes the sidecar rather than leaving a stray empty file that would invite the question of what it is for. One test asserts Write does not touch the .owm itself, because Requirement 3.7's whole point is that ADP's own data never enters a file another ecosystem owns - not even as a comment. The class doc records why this module uses a sidecar where mindmap-diagram Requirement 3.5 chose the .adp trailer: a .mm node carries a native ID so the mindmap has identities to USE, whereas an .owm element has none at all, so this module must store one per element - a growing, per-element structure, which is what the sidecar rule exists for. WHAT IS NOT DONE: Reconcile - matching recorded entries to elements by key, assigning a fresh ShortGuid to an unmatched element, discarding an unmatched entry - needs the parsed map, which is task 5's output.
