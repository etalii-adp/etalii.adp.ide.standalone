# Implementation Log: Task 2

**Summary:** The four reporting modules migrated onto the shared view report, and the ansible defect fixed.

**Deleted:** four private `reportView` bodies, four `VIEW_REPORT_DEBOUNCE_MS` constants, three `shownRectOf` definitions and four `Viewport` interfaces. 210 lines removed for 108 added across 9 files, and the removed ones were the copies. Requirement 3.2 verified by grep: no module client retains any of the four.

**The proof the extraction reproduces them is what was not touched.** `MindmapCanvas.test.tsx`, `C4Canvas.test.tsx` and `PipelineCanvas.test.tsx` are unchanged and green. Requirement 5.1 asked for the same reports at the same moments; an extraction that had needed those tests edited would have been an extraction that changed behaviour. The only test file modified in the whole task is ansible's, which is the disclosed exception.

**azure-pipeline is the case Requirement 3.3 was written for.** It calls `shownRectOf(box)` with no second argument and gets its former bare-box result from the shared function's no-surface branch — no `null` passed, no argument it has no use for. That equality is pinned by its own test in task 1 precisely because it is what keeps this module unchanged while its private copy is deleted.

**ansible-structure: the fix, and its guard.** Its report effect carried no `loading || failed` guard and sat before the component's `if (failed)` / `if (loading)` early returns. Hooks run regardless of a later return, so it reported a view of nothing before the first delta had said what there was, and reported again to a connection the backend had just answered was unroutable. The shared hook carries the guard and both reports stop.

`aDiagramThatIsLoadingOrFailed_ReportsNoViewport` was written **first**, against the unmigrated canvas, and watched to fail — *"reported while loading: expected vi.fn() to not be called at all, but actually been called 1 times"*. After the migration it passes, and it fails again on demand: setting `ready: true` in the migrated canvas reproduces the original failure message exactly. Its sibling, `reports the viewport once the diagram is ready`, exists because a guard that suppressed everything would pass the first test while silently removing the feature — the two together say the guard suppresses those two states and nothing else. The module's test mock previously stubbed `reportView` as a no-op `() => {}`, which could not have caught this; it is now a `vi.fn()` spy cleared in `beforeEach`.

**One thing the migration required that the design did not anticipate.** ansible needed a ref for its view. It read `effective` from the closure on each render, which its own dependency array made correct; the shared hook converts at fire time instead, which is what lets a canvas report its *live* view and its *measured* surface rather than a value captured at render. So `effectiveRef` was added alongside the existing `boundsRef`. This is a consequence of the design's deliberate choice to take `convert` as a function rather than a rectangle, and it is the first place that choice had a visible cost — a small one, and it buys the fire-time read that mindmap and c4 already depended on.
