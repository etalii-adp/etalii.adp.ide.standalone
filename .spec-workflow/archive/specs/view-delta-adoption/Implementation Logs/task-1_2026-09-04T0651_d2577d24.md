# Implementation Log: Task 1

**Summary:** The shared client half of the view-delta loop, lifted from the reference rather than rewritten.

**What was centralized:** `Viewport`, `ViewBox`, `VIEW_REPORT_DEBOUNCE_MS`, `shownRectOf(box, surface?)` and `viewReportOf(client, projectId, watchId, path)` in `viewReport.ts`; `useViewReport({ view, report, convert, ready })` in `useViewReport.ts`. Lifted verbatim — the `viewKey` template, the ref indirection, the swallowed `.catch` — because task 2 must prove this reproduces four working modules exactly, and a tidy-up here is what would make that impossible to prove.

**Requirement 3.3 settled on evidence, not preference.** azure-pipeline's private one-argument `shownRectOf` is not a variant of mindmap's and c4's two-argument one: it is character-for-character the branch those two return when there is no laid-out surface. So one function with an optional surface reproduces all three exactly, a caller without a surface passes no argument rather than `null`, and the no-surface result is a complete answer rather than a degraded one. That equality is pinned by its own named test, because it is what keeps a bare-`viewBox` canvas unchanged when task 2 deletes its copy.

**Requirement 3.6 holds by construction:** the hook takes a `report` function and knows nothing about how the module opened its stream, so adopting the report never drags a hand-rolled open loop into a `useDiagramStream` migration.

**Eighteen tests, each verified by sabotage rather than by passing:**

| Sabotage | Test that fails |
| --- | --- |
| `viewKey` built from `x`/`y` alone | reports on a zoom, not only on a pan |
| debounce fires immediately | reports once for a burst of changes, not once per change |
| ref indirection removed | does not re-report merely because the report or conversion was rebuilt |
| `ready` guard removed | does not report while the diagram is loading or has failed (and: reports once the diagram becomes ready) |
| no-surface branch returns anything but the bare box | the three bare-box cases |

**A defect in my own verification, worth more than the tests it checked.** The `ready` sabotage was a no-op on its first attempt — the replacement pattern was written with LF newlines against a CRLF file, so nothing was modified and eighteen tests passed against unchanged code. Read naively that says "the guard is not needed"; it actually said "the sabotage never happened". Re-run with an assertion that the pattern matched first, it fails two tests as designed. **A sabotage that cannot prove it applied is worth nothing**, and this repository's line-ending policy makes LF-pattern edits silently no-op on every source file. Every sabotage in this spec now asserts before writing.

**Two findings recorded, neither acted on:**

1. **`ViewBox` is a sixth duplicated declaration** — identical in ansible-structure, azure-pipeline, c4, helm-charts, mindmap and wardley-map. It is defined in the shared module for the signature's sake, but no module is forced to migrate: TypeScript is structurally typed, so each module's local `ViewBox` satisfies the shared parameter unchanged. Centralizing it is a canvas concern rather than a view-report one and is out of this spec's scope; raised rather than absorbed.
2. **A fresh worktree's first full client suite fails misleadingly.** `src/client/src/generated/` is both gitignored and tracked, and `npm install` regenerates it; a suite run racing that codegen reports 59 failed files with `Failed to resolve import "../generated/..."`. It looks exactly like a broken build and is not — re-running after codegen settles gives 84 files, 827 tests, exit 0.

Gates: client suite exit 0 (84 files, 827 tests), typecheck exit 0. Backend untouched by this task.

### Functions

#### shownRectOf
- **Purpose:** Converts a canvas view box to the rectangle the backend understands. With a laid-out surface it accounts for preserveAspectRatio="meet" widening the roomier axis, so the backend does not cull elements the reader is looking straight at. Without one - no argument, a null ref, jsdom, or before the first measure - it returns the bare box, which is exactly what a bare-viewBox canvas computed for itself before this was shared.
- **Location:** src/client/src/diagrams/viewReport.ts
- **Signature:** (box: ViewBox, surface?: SVGSVGElement | null): Viewport
- **Exported:** Yes

#### viewReportOf
- **Purpose:** Builds a module's reportView: the unary UpdateView call correlated to the open stream by watchId and path, with the advisory failure swallowed. Built on the client the module's stream hook already returned, so adopting the report does not require adopting useDiagramStream (Requirement 3.6).
- **Location:** src/client/src/diagrams/viewReport.ts
- **Signature:** (client: Client<typeof DiagramService>, projectId: Uint8Array, watchId: Uint8Array, path: readonly string[]): (viewport: Viewport) => void
- **Exported:** Yes

#### useViewReport
- **Purpose:** Reports the canvas's view once it settles and on every later change. Keyed on the view's four values, debounced, guarded on readiness, and reached through refs so a report rebuilt each render does not re-fire the effect. The report observes the view rather than being wired to any gesture, which is what makes the loop hold for pans, thumbs, zooms and programmatic reveals alike.
- **Location:** src/client/src/diagrams/useViewReport.ts
- **Signature:** (options: ViewReportOptions): void
- **Exported:** Yes
