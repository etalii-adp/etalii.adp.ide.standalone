# Implementation Log: Task 3

**Summary:** PROMPT SIDE: the folder's existing folder-subject registration is computed ONCE for the whole tree — every folder-subject type asks the same question of the same folder, and the answer cannot change while one prompt is being built — and each option is annotated from it. A folder-subject type gets the suppression sentence and no suggestion, plus an unavailable_reason naming the existing file when the folder already holds one. Both registration shapes count, bare .adp and legacy named alike, because what makes a folder registered is the type its registration routes to, never the file's name. The prompt-level NameField stays: a file-subject type still needs it, and serving both kinds from one dialog is the point. COMMIT SIDE, inserted into the existing check order rather than rearranging it: after the option resolves, a folder-subject type ignores any submitted name (logged at Warning, because a stale client should be visible rather than silently obeyed), skips ValidateName entirely, re-consults the folder and refuses if it is already registered, and writes DiagramFileName.Extension. ValidateName is skipped rather than called with an empty string, because it rejects an empty base name precisely so that nothing creates a file called ".adp" — the file this path creates on purpose, so the guard would refuse the one case it exists to prevent everywhere else. The re-consultation is deliberate rather than trusting the prompt: the dialog may have been open while another registration landed. DiagramFileRouter is a REQUIRED constructor dependency; an optional one would have to degrade to "no folder is ever registered", which is not a safe default but a silent one — it turns the collision check into a check that always passes. Six hand-construction sites updated, not the five a grep suggested: the sixth had a different shape (an expression-bodied helper with an inline catalog) and the compiler caught it rather than the pattern assertion. TWO FINDINGS, both exposed rather than caused by this change. (1) The integration flow tests were already choosing a folder-subject type: FirstLeaf returns the first selectable option and "ansible" sorts first, so every assertion in AddDiagramFlow.Tests and CreateDiagramFileFlow.Tests about naming, validation and collisions was being made against a type that does not take a name — harmless only while folder-subject types behaved like every other, and eight tests failed at once when they stopped. Both helpers now skip name-suppressed options, which is the property those tests actually want. (2) AddDiagramFlow's FirstLeaf only ever searched the FIRST vendor group: it returned FirstLeaf(children) unconditionally instead of continuing to the next vendor. Invisible while that group's first leaf was always the answer. It now searches every vendor and its throw message says what it was looking for. VERIFICATION, including one test that was wrong when it first passed: sabotaging the collision check to "never collides" failed only the legacy-named case — creating ".adp" where ".adp" already exists is refused by the generic already-exists check too, so Assert.Contains(registration, error) passed with the folder check removed entirely. The assertion now demands the exact sentence and both cases fail without the check. That is the vacuous-guard shape found by sabotage rather than by review.
