# Implementation Log: Task 2

**Summary:** DiagramOptionTree.Build now takes Func<DiagramDefinition, ContextOptionAnnotations>? annotate in place of Func<DiagramOrigin, string>? suggest, with a new record carrying SuggestedValue, NameSuppressedReason and UnavailableReason together. Taking the DEFINITION rather than its origin is the point of the change rather than a detail: whether a type registers a folder is a property of the definition (HasFolderSubject), and an origin cannot be asked. Task 3 needs that answer and this is the seam that can give it. The three values travel together because they are decided together — whether a type wants a name, what that name should default to, and whether it can be chosen here are one judgement about one option, made with the folder and the definition both in hand; three separate callbacks would read the same subject three times and leave room for two answers to disagree. STRUCTURAL IMPROVEMENT worth noting beyond the task text: both leaf shapes — a subtype, and a type that is itself a choice — now go through one Leaf helper. The old code built the two separately and called Suggestion in each, so the three annotations could have been applied to one and forgotten on the other; that risk is now structurally absent rather than avoided by care. Groups still receive nothing. Both call sites moved: the file-registration branch (non-container target) still passes no callback, and the folder branch passes one returning today's suggestion and nothing else, so document-subject behaviour including the suggestion is unchanged.
