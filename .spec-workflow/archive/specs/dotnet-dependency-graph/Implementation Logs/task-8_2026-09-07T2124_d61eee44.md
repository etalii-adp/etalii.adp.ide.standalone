# Implementation Log: Task 8

**Summary:** Layout adopted rather than redefined (Requirements 6.1-6.6). ORDER NOTE: the computation half landed a commit ahead of task 7 (worktree 852f56b9), because a session cannot emit an element without a position - the reorder is recorded here rather than left for a reader to infer from commit order.

DotNetDependencyGraphLayout computes and nothing else: projects layered by dependency depth, one layer beyond the deepest thing they reference, with packages banded past the last project layer because this type reads direct references only and a package is therefore always a leaf. Reading, writing, merging and pruning the stored layout are core's RegistrationLayout, offered to every module - so no layout mechanism is added here, which is the task's own tripwire and it did not fire. The overlay is RegistrationLayout's semantics applied in DependencyElementMapper: a stored position wins for its own element and computed positions hold for the rest (6.3), and a stored id matching no element is simply not applied, core dropping it on the next write (6.4). Reposition dispatches core's SetRegistrationLayoutCommand, so a drag is one undo away (6.6) and elements drag although the subject is read-only (6.5) - arrangement is a view concern, not an edit to the solution.

Two properties guarded beyond the arrangement. The order inside a layer is stable, because a computed layout that moved between two identical readings would make a stored position look wrong the first time the diagram was reopened - the user's arrangement appearing to drift when nothing changed. And a reference cycle TERMINATES: MSBuild refuses one so it cannot arrive from a working solution, but a diagram derived from files that may be wrong must not hang over being wrong, and without the visiting set that test does not fail, it never returns. Both seen to fail first, along with packages left unplaced (a forgotten node draws at the origin under whatever is really there, which reads as a rendering bug rather than a layout one).

Verified end to end by the session's integration tests: a reposition reaches the .adp and nothing the build owns is touched (the .csproj and .slnx are compared byte-for-byte before and after), and a stored position wins for its element while the others stay computed. 64/64 green.
