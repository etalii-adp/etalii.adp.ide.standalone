# Implementation Log: Task 4

**Summary:** DependencyGraph plus ProjectNode / PackageNode / DependsOnEdge / DependencyGraphModel (Requirements 3.1, 3.4, 3.5, 6.7). Derivation takes readings and returns a graph with no filesystem in it, so the readers stay testable without a graph and the graph without a disk - the boundary the design asked to be kept sharp.

THE GUARDING TEST, and it was seen to FAIL first exactly as the task demanded. A package's element id is package:<id> with NO version. The test derives the same solution twice, differing only by a version bump, and asserts the element id does not move. Sabotaged with ids built as package:<id>@<version> - the precise alternative the design considered and rejected - the test went red. That decision is load-bearing because a stored position in the .adp layout: block binds to an element id: a version-carrying id would change on a package bump, the commonest change a solution undergoes, and the stored position would then bind to an element that no longer exists and be dropped on the next write - Requirement 7.2 breached at the moment it matters most. Review left this unchallenged rather than endorsed on its merits, which is why the test pins it rather than the prose alone.

The cost is paid in Requirement 3.5, deliberately: a package referenced at two versions is ONE element carrying both versions and marked HasVersionConflict. Collapsing loudly is what 3.5 asks for; collapsing silently is what it forbids. A version that could not be discovered marks the conflict WITHOUT entering the version list, because a null is not a version. Requirement 3.4 falls out: one element per package id, several incoming edges, sharing shown rather than repeated.

Other decisions guarded: a project id is its path relative to the solution rather than its name, so renaming an assembly keeps the box where the user put it (the other half of 6.7); a ProjectReference pointing outside the solution's project set is REPORTED rather than drawn or dropped - no node the solution does not contain is invented, and no declaration vanishes silently; the .NET version is absent rather than guessed when the framework does not name one (netstandard2.0 yields null, not a fabricated value); one project declaring a package twice is one edge. 33/33 green.
