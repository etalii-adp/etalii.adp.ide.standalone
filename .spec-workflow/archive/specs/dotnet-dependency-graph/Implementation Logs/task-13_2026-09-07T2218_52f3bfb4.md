# Implementation Log: Task 13

**Summary:** Scale, the ruled answer. Architect 1 ruled degree-based package filtering - on by default, always visibly stated, no node limit, no project grouping - and this replaces the layer wrap as task 13's answer. The wrap stays as layout hygiene and is labelled as such; it is neither a limit nor a grouping, and the 5,850-unit ribbon it removes is a separate measured fact.

RE-MEASURED WITH THE CURRENT READER RATHER THAN TRUSTING THE RULING'S FIGURES, and the two differ in ways worth recording. Mine: 104 projects, 17 packages, 427 edges (272 project + 155 package), 0 failures, degrees 26 26 26 19 18 14 6 6 4 2 2 1 1 1 1 1 1. The ruling's: 102 projects, 340 edges, 149 package edges, top four 25/25/25/18. The project delta is +2 because THE GRAPH NOW INCLUDES ITS OWN MODULE - this type's project and test project landed between the two measurements - and each package degree is +1 for the same reason. The edge delta is larger and has a different cause: 272 project edges against roughly 191 implies the ruling's instrument read wildcard ProjectReferences literally, which is the defect this module fixed in task 3. The package finding is untouched by that, because project-reference expansion does not create package edges, so the ruling stands on its own numbers as well as on mine.

TWO THINGS THE RULING COULD NOT HAVE KNOWN, both consequences of taking "degree, never a curated name list" seriously. (1) NO THRESHOLD SEPARATES Grpc.Tools (19) FROM Serilog (18). A degree rule catching the fourth hub the ruling names necessarily catches Serilog too. That is the rule working rather than failing, and it is the strongest argument for degree over names: a name list would have kept Serilog by opinion. (2) The share alone misfires on small solutions - at 15% a seven-project solution hides a package two of them use, which is a third of the solution rather than its background. Hence AmbientFloor = 5: below a handful of dependents there is no crowd to disappear into, and it is why the shipped four-project example draws complete.

NAMING, DELIBERATELY NOT THE RULING'S WORD. The marking is called ambient, not near-universal. The measured cut has to sit at 15% to catch what the measurement identifies, and a reader meeting "near-universal" on a package referenced by 16 of 104 projects would rightly reject it. The ruling's sentence - a near-universal edge is noise wearing the shape of information - is quoted in the code as the reasoning; the identifier names what is actually measured, which is background-ness rather than ubiquity.

MARKING, NEVER TRUNCATION. The derivation keeps every node and every edge; IsAmbient is a flag the canvas reads. So "Show them" restores from the model rather than re-deriving, and a test asserts that an ambient package still carries all forty of its edges. Visibly stated is implemented as part of the feature rather than a nicety: the canvas names the hidden packages, gives the count and the grounds, and restores them in one click - and emptiness is judged on the whole graph, so a solution whose every package was ambient cannot report itself as having no projects.

FIVE SABOTAGES, EACH SEEN TO FAIL FOR ITS OWN REASON: nothing ever marked ambient (3 tests red), the floor removed (only the small-solution test red), a fixed count in place of the share (only the share test red), a derivation that drops ambient edges (only the still-in-the-graph test red), and a client filter that hides a node but keeps its edges (only the edge test red).
