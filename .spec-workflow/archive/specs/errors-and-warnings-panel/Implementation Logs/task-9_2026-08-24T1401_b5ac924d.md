# Implementation Log: Task 9

**Summary:** Added both Validate providers and routed the problems source. ValidateContextActionProvider (Hierarchy scope): problems.validate, labelled "Validate" on a router-recognised diagram and "Validate folder" on a folder, mdi-check-circle-outline, shortcut F6 as data; anything else gets no entry at all (a .txt gains no greyed item, Requirement 6.6). Execute runs ProjectValidator - Project scope for the root (validating the root is Validate all), Folder scope with ReplaceFor([folder]) otherwise, File scope with routing-derived covered paths for a diagram - and returns Completed; a vanished target fails without writing. Both call the new IProblemStore.BeginValidating (state Validating while the old list stands, Requirement 1.6) and neither prompts, so ValidateAsync/CommitAsync throw like HistoryContextActionProvider's. TryResolveTargetAsync gained the problems source -> ProblemsPanel-scope target, and a new ProblemsContextSourceResolver lets the panel select itself on focus (CanResolve problems source; no nesting, no tracking) - without it the panel's select() would be rejected and Validate all could never reach the ribbon. All registered in AddProblems. 11 new provider tests; existing AddDiagramFlow root-baseline test updated (Validate folder on the root is legitimately enabled). 438/438 backend green, style clean.
