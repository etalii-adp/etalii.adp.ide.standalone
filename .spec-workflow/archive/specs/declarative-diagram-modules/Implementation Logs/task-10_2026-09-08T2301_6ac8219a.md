# Implementation Log: Task 10

**Summary:** The reference migration: dependency-graph draws nothing itself.

Its CustomShapeRef existed to wrap the shared SpanElement with three classes and an edge rule, and both are declarations now - shape: "span", four classNames (two conditioned on the canvas's own state), one truncating editable label, and edgeSides: "horizontal" on the anchor set. The canvas loses 39 lines, and ALL FORTY-FIVE OF ITS TESTS PASS UNCHANGED, which is the acceptance this migration was ordered around: the tests were written against the custom renderer and they cannot tell that it is gone.

THE MIGRATION FOUND TWO GAPS THE SUFFICIENCY TABLE COULD NOT, which is exactly what a reference migration is for. Both are about what happens AROUND the drawing rather than what an element draws, which is the honest reason a row-by-row reading missed them.

G21 IS THE SERIOUS ONE AND IT WAS ALREADY BROKEN BEFORE THIS TASK. Task 2 replaced `label` with `labels` for drawing and left the inline-editor placement reading only the deprecated rule - so any type marked editable in the new vocabulary silently got no editor at all. Every unit test of layoutLabels would have stayed green forever, because the editor is not something layoutLabels does. It is now the editable declaration that decides where the editor opens, over the LINE rather than over the element, which is what a three-line card needs.

G20 is the axis-constrained edge attachment: three canvases attach on the side facing the other end whatever the angle, because the notation reads left-to-right and an edge leaving through the top reads as a different relation.

AND A SABOTAGE FOUND A HOLE IN THE MIGRATION'S OWN SAFETY NET, which is the part worth reading. Removing edgeSides left all forty-five module tests GREEN. This module routes with its own path builder, which takes the endpoint BOUNDS and picks its own anchors, so the attachment point never reaches the drawn line here. The declaration would have looked verified and been nothing of the kind. The guard therefore lives in the library, where it stands for the two modules that have no such shelter - dotnet-dependency-graph and timeline, which migrate next - and the module's readme records the hole rather than hiding it.

Three sabotages in all: the node's own class dropped (3 tests red), the label's truncation dropped (1 red), and the edge constraint dropped (0 red - the finding above). Two more on the library: the axis constraint ignored, and a declared label given no editor.

One deliberate library choice, because the alternative was worse: a declared label leaves its anchor to CSS when it is the default, and `library-element-label` carries the rule. An inline attribute for the default would override a module's stylesheet for no reason, and every shared element leaves the anchor to CSS today - so this keeps the library self-contained AND lets the module's test pass unchanged, rather than editing the test to fit the implementation.

All four gates green on the merged tree, and the code verified onto develop with merge-base --is-ancestor: 119 files, 1239 client tests, typecheck zero, format zero, 5006 backend tests with none failed.
