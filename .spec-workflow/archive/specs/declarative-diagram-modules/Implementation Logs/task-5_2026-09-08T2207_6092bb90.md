# Implementation Log: Task 5

**Summary:** `actions`, anchor enablement, and the library owning the keyboard (Requirements 2.4, 2.6, 2.7, 2.8, 3.4).

TWO THINGS HAD TO DISAPPEAR AND BOTH HAVE. The four hand-written shortcut lists go because there is no list to write: shortcutKeysOf DERIVES the key set from the declarations. The synthesised {key:"Delete",ctrl:false,shift:false,alt:false,meta:false} goes because a delete gesture dispatches a declared action ID - a module has no way left to name an action by manufacturing a key event.

MEASURED BEFORE BUILDING rather than taken from the requirements: seven canvases spell it ["F2"], two ["F2","Insert","Tab","Enter"], one ["Insert","Enter","F2"," ","Tab"], one ["F2","Insert"] - eleven canvases, four spellings - and nine files carry a synthesised Delete. Both figures match the specification exactly, which is worth knowing because a figure that did NOT match would have meant the tree had moved under the design.

Requirement 2.8's distinction now exists in the contract: a type declaring no rename HAS none, and a type declaring one disabled has one currently unavailable. Today both look identical - like a handler nobody wrote.

ONE RULE CHOSEN DELIBERATELY: an action whose enablement cannot be determined does NOT fire. Firing is the irreversible half, and the alternative is a delete that happens because a path was misspelt. Its sabotage - reading an unresolvable flag as enabled - reddens that test AND the anchor one, which is the pairing showing one rule governs both.

Modifiers are compared explicitly rather than loosely. A declaration naming ctrl must not fire on a bare press and one naming nothing must not fire on a modified press; an unstated modifier means "not held", which is what every existing call site means by it.

ANCHOR ENABLEMENT ON THE SAME MECHANISM - the half of the anchor declaration that was missing. AnchorSet said only WHERE anchors are, and all twenty-nine declarations in the tree are {kind:"edge"}, so the positional half has never once been needed while the half modules actually want had nowhere to go. AnchorEnablement adds visible and enabled as DeclaredFlags, the same type actions use, because "connectable only when the model says so" is the same question as "enabled only when the model says so" and two mechanisms for it would be one too many.

INERT UNTIL A MODULE ASKS. A definition declaring no actions behaves exactly as before - the old element-deleted path still fires - and the test asserts BOTH halves of that, because the negative alone would pass if the element had never been selected.

The existing event-roster test grew by one member. That is the roster being extended rather than behaviour changing: it asserts Required<DiagramEventHandlers> precisely so that adding an event kind forces adding its handler, which is the guard working as designed.

Sabotages: an unresolvable enablement reading as enabled, and modifiers ignored. Four facts red between them, none overlapping. 1191 client tests, typecheck zero. Worktree commit on claude/ddm.
