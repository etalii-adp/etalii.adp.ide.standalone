# Implementation Log: Task 12

**Summary:** The rdf family, all four readings, seven custom shapes gone (Requirements 9.3, 9.4, 8.1).

THIS IS THE CASE THE COLLECTION BINDING WAS DESIGNED FOR, AND IT CARRIED IT. The card that made the whole argument for `labels` - a header, a conditional badge line, and ONE LINE PER ROW - is a declaration now. The fixed-three-slots alternative that would have served c4 and left this family exactly where it was is visibly the wrong design rather than an asserted one.

Four additions, each named by the rows that forced it, and none by taste:

A STACK'S START IS BINDABLE. An owl card's rows begin below its badges when it wears any; a SHACL shape's rows begin below however many targets it declares. Both are numbers the module already computes to SIZE the card, so a fixed start would have put every badged card one row out - and silently, because the rows would still be drawn, just over the badges.

AN `each` MAY COMPOSE FROM PARTS. A SHACL row reads its path, or the words "SPARQL constraint" when it is one: a choice per ENTRY, which a template cannot make and a second collection over the same list would let drift.

A LABEL'S CLASS MAY BE BOUND, resolved against the entry, because a sparql row wears its own.

`on: "shape-inner"` is the fourth. OWL doubles an equivalent class's outline and names the ring itself - `owl-shape-inner`. The library must not invent that by suffixing a declared class: a class a module did not write is a class its stylesheet has not got.

A REAL DEFECT FROM TASK 2, FOUND HERE AND FIXED FOR EVERY MODULE. Every shared element drew a `<text>` even when its label was empty - the placeholder from when a shape drew its own single label. A type declaring `labels` passes an empty one, so a blank text node sat BEFORE the real lines, and that is what a reader, and `querySelector("text")`, finds first. Two owl tests failed on it.

A SABOTAGE FOUND NOTHING AGAIN, WHICH IS THE FINDING: `start: 0` left all forty-one rdf tests green, because none of them checks where a card's rows sit. The guard for that is now in the library, exact on both cases, and reddens when a bound start is ignored.

AND I CUT TOO MUCH. Removing owl's three shapes by their file boundaries took `edgeType`, the kind lists and the anchor set with them. Restored with `git show HEAD:` rather than retyped - the same rule as never re-applying a deletion in flight, for the same reason.

All four gates green on the merged tree; 1252 client tests; the code verified onto develop with merge-base --is-ancestor. rdf has no `CustomShapeRef` left, checked by grep rather than by eye.

ONE CORRECTION TO THE BOARD, since it would misdirect task 14: the scrum master's note says `DiagramBackgroundRef` survives "because wardley-map and sparql still use it". Sparql does not - it declares no background at all, and its `sparql-region` is a custom SHAPE. wardley-map is the only user, which is what the tasks document already says, and what a grep for `render:` under a background confirms.
