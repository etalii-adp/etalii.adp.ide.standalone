# Implementation Log: Task 5

**Summary:** ProjectValidator now routes a DiagramProblemFileLocation's file into both the attribution path and the statsPath staleness pin, via a new private LocatedFile(problem, root) helper. The pin is the half that matters: a folder diagram's .adp never changes, so pinning its problems there would leave every verdict looking fresh for ever, while editing the file that declared the mistake is what should mark it stale. LocatedFile refuses a rooted path or one that escapes the project - the location comes from a module, and a module is trusted to stay inside the project no more than a user-editable body: header is - reusing the existing IsInside helper and logging a warning. A refused location falls back to the diagram's own file, so the problem is still reported, merely attributed less precisely, rather than being dropped. Two guards: one asserting a located problem is stored against declaring.yml with that file's own Length and LastWriteTimeUtc (it would read flow.adp before this change, so the test genuinely fails without it), and one asserting an escaping ../../elsewhere.yml falls back to flow.adp.
