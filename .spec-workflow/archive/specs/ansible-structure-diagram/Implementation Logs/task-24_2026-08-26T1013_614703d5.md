# Implementation Log: Task 24

**Summary:** ZeroWrites.Tests: four tests proving Requirement 1.1 and the spec's first non-functional requirement. The headline snapshots the fixture by CONTENTS AND MTIME (a file rewritten with identical bytes is still a file this module wrote, and would show as a touched mtime in someone's git status), then exercises every read path against the REAL components - open a session, baseline, narrow and widen the viewport, select and describe every node and every edge, attempt SetAsync on each, attempt MoveElementAsync, and run the validator - and asserts the tree is byte-identical. Both refused writes are included deliberately: a refusal that still touched the disk is the bug actually worth guarding against, and mocking the refusal away would guard nothing. Three supporting tests: reading creates no cache file or sidecar of its own; reading takes no lock, so the text editor the user is fixing their YAML in can still save over the files; and the module's public surface names no write verb. TWO MISTAKES OF MINE, both instructive. (1) The public-surface test initially flagged AnsibleEdge.WriteTo and three siblings - protobuf gives every generated message a WriteTo that serializes to a STREAM, nothing to do with files. Excluded by namespace, which the .Wire sub-namespace from task 14 makes trivial; a second unplanned dividend from that decision. (2) The snapshot test failed at first and NOT because of a write. Assert.Equal over Dictionary<string, (byte[], DateTime)> compares the ValueTuple with its own Equals, which compares the byte[] inside BY REFERENCE - so two reads of an unchanged file are never equal. Evidence it is the tuple and not arrays generally: my task-16 MoveElement_ChangesNothingOnDisk uses Dictionary<string, byte[]> with a bare Assert.Equal and has always passed, because xUnit's comparer does decompose a nested collection structurally. This is the SECOND time reference-vs-structural equality has bitten me in this spec (task 10 was the first, on record equality over IReadOnlyList members). Replaced with AssertUnchanged, which reports created/removed files by name and then compares contents with SequenceEqual and mtimes per file - so the failure message names the offending file, which for this test above all has to be immediately actionable. Verified: build 0 errors; module 177/177; Backend 494, Diagram 62, Adp 37, Mindmap 146, C4 400 (19 skips) all green.
