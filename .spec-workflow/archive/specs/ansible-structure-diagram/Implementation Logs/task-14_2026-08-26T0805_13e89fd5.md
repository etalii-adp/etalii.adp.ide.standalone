# Implementation Log: Task 14

**Summary:** Added src/diagrams/ansible-structure/api/ansible-structure.proto (AnsibleElementPayload, AnsibleRoleContents, AnsibleInventoryGroup, AnsibleEdge, AnsibleElementKind, AnsibleEdgeKind) and wired the module's api folder into the client's generate script, which is what makes the stubs appear at all - buf generate is invoked per api folder, so a new module is invisible until package.json names it. THE FINDING: generating into the module's own C# namespace, as every other module does, is a hard CS0101 collision. This module's wire shapes and its domain model share four names - AnsibleEdge, AnsibleEdgeKind, AnsibleRoleContents, AnsibleInventoryGroup - because they are genuinely the same concepts flattened for the wire. Fixed with option csharp_namespace = "...AnsibleStructure.Wire": renaming the wire types to dodge the clash would leave a reader guessing which "AnsibleEdgeMessage" belonged to what, while a sub-namespace says it once and every use site then reads Wire.AnsibleEdge versus AnsibleEdge. Recorded in the proto and in api/readme.md so task 15's mapper does not rediscover it. Note the TypeScript side is unaffected - it keys off the proto package etalii.adp.ansible, not the C# namespace. Also carried on the payload beyond the design's sketch: `hollow` (so a hollow role is visibly hollow without the client recomputing it from the contents counts), `groups` and `file_count` (so an inventory and a variable folder can label themselves).
