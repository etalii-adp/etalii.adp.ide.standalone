# Implementation Log: Task 4

**Summary:** Added DiagramProblemFileLocation(string RelativePath, uint Line = 0) as a third DiagramProblemLocation case and carried it through the whole problem wire: CachedProblem, ProblemBroadcaster, context.proto (a new ProblemFileLocation message on field 3 of the ProblemLocation oneof - a new number, never a reused one), and ErrorsWarningsPanel. The panel gained a locatedSegments() helper that pathText, the row and the activation handler all use, so a folder-subject problem prints and reveals the file that declared the mistake rather than the one-line .adp. CachedProblem keeps FilePath as its own init-only property rather than reusing the line case: a line location means "line N of the diagram's own document" and a file location means "line N of that other file", and collapsing them would reopen the wrong file after a restart. FilePath is nullable with a default so a cache written before this existed still deserializes. Three guards added: two ProblemStore round-trip tests (with a line, and with line 0 which must stay 0 rather than becoming a real-looking position) and one ProblemBroadcaster test asserting the path crosses as segments and that the problem's own attribution path is still the .adp - what a problem is attributed to and what it points at are two different questions. Two client tests cover the panel end. Verified: build 0 errors; EtAlii.Adp.Backend.Tests 490/490; client typecheck clean and 377 tests passing, ErrorsWarningsPanel.test.tsx 18/18. Environment notes for later client tasks: node_modules does not exist in a fresh worktree, so `npm install` is needed before `npm run generate` (142 packages, ~3s); @bufbuild/buf's postinstall is gated by the repo's allowScripts policy and was NOT approved, but buf generate works regardless. src/client/src/generated/ is gitignored (.gitignore line 9) yet eight *_pb.ts files are tracked anyway - context_pb.ts is NOT among them, so this proto change reaches the client only via npm run generate, which the pretest/prebuild/pretypecheck hooks run. Regenerating leaves the eight tracked files stat-dirty with an empty content diff (line-ending churn); they were restored rather than committed.
