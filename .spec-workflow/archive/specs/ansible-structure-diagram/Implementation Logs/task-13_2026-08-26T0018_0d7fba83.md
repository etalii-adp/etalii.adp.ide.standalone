# Implementation Log: Task 13

**Summary:** AnsibleLayout.Compute(graph, metrics?) returning IReadOnlyDictionary&lt;string, AnsibleBox&gt;, plus AnsibleMetrics and AnsibleBox. Pure - no file access, clock or randomness. Ranking: playbook depth is the LONGEST PATH over ImportsPlaybook edges (so a playbook always sits right of everything importing it, however many hops away), a play sits one column right of its own playbook, roles share the column after the deepest of those, task files the one after. Inventories and variable folders get NO rank, which is how Compute knows they are band material - they go in a single row beneath the flow, separated by BandGap rather than RowGap because the band is a different kind of thing and the space says so before any label does. Within a rank, order is the node's index in graph.Nodes: that IS declaration order, it is already deterministic, it is unique so it needs no tiebreak, and it keeps a role beside the play that first reached for it rather than sorting the story alphabetically. A column is as wide as its widest member, so a long name pushes the next column right instead of running into it. Two robustness details: Depth() carries a visiting set so an import cycle terminates - Ansible would refuse such a project, but ADP reads folders somebody is still editing and a half-written cycle must not hang the diagram - and there is a test that builds a real a.yml/b.yml cycle in a temp folder to prove it. AnsibleBox is its own file rather than sharing one with AnsibleMetrics; the mindmap module puts MindmapBox inside MindmapMetrics.cs, which is the one-entity-per-file rule bent, so I did not copy that part. 13 new tests including an O(n^2) no-overlap sweep over two fixtures. Verified: build 0 errors; module 88/88; no regression across Backend 494, Diagram 62, Adp 37, Mindmap 146, C4 393.
