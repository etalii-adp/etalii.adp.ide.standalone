# Implementation Log: Task 15

**Summary:** AnsibleElementMapper: Visible(project, graph, viewport) producing core DiagramElements, and Diff(previous, current) producing deltas. Element types are ansible/structure+playbook|play|role|taskfile|inventory|vars|edge; ids come from AnsibleNode/AnsibleEdge unchanged. DISCOVERED WHILE IMPLEMENTING: the core DiagramElement carries X and Y but NO size, so the box the layout measured has to ride the module's own payload - the mindmap does exactly this and its comment says why (a client-side guess at the size is what made wide nodes overlap their neighbours). Added width and height to ansible-structure.proto (fields 13 and 14) and regenerated; the design's proto sketch had omitted them. Decisions: (1) Two of the four delta kinds are NEVER emitted and a test asserts it - nothing on this diagram folds so group/ungroup have no meaning, and nothing is edited so a push is Remove-then-Add for what actually differs. Diff only removes ids that genuinely disappeared, since Add is an upsert. (2) The viewport rule is the mindmap's and for the mindmap's reason: what intersects, plus EXACTLY one hop of graph partners, because the canvas draws a connector from the boxes at its two ends and a culled partner would lose the line; following partners of partners would walk the whole graph and deliver the entire project. (3) An edge whose target is missing or unresolvable still draws, from its source to nothing - that is how a reader sees something is missing rather than seeing nothing at all - so the delivery check treats an empty TargetId as satisfied. (4) A single-play playbook carries its play's hosts pattern on the playbook payload, because no play box is drawn for it and the reader would otherwise never see the pattern. (5) The project's annotations ride playbook nodes, where a reader asking "what is this project" will be looking. The Wire alias from task 14 works exactly as intended: `Wire.AnsibleEdge` versus `AnsibleEdge` reads unambiguously at every use site. 17 tests including one asserting no payload property name contains Colour/Color, so the index-not-a-colour rule cannot erode. Verified: build 0 errors; module 105/105.
