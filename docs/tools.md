# Tool types

A catalog of the tools EtAlii.Adp offers or could offer: diagrams, designers and editors. The diagram types are adapted from a broader reference overview of software/IT architecture diagram styles, grouped by the methodology/notation family they belong to (where one exists); designers and editors follow them. Each entry tracks how far along ADP's own support for it is, alongside the theory and a visual example for the notation itself.

**This document is a living catalog — see the note in [CLAUDE.md](../CLAUDE.md) about keeping it updated whenever a new tool type is identified or its state changes.**

## Legend

**Tool** — the tool type's display name: one name, spelled and capitalised the same in every host, the catalogue, the site and Notion, and a name rather than a description ([ADP terminology](https://github.com/etalii-adp/etalii.adp/blob/develop/docs/terminology.md)). What the notation covers is said in **Example**.

**Kind** — which of the three kinds of tool it is, by the tests of ADP terminology applied in the order editor, diagram, designer: an **Editor** when typing text is the main thing the user does, a **Diagram** when its elements are connected, a **Designer** when it is a form-based layout with nothing connected.

**State** — how far ADP's own support for the tool type has progressed:

| Icon | State | Meaning |
|---|---|---|
| 💡 | Identified | Recognized as a candidate tool type; no spec yet |
| 📝 | Specified | A requirements/design spec exists (`.spec-workflow/specs/`) |
| ⏸️ | To-do | Spec approved and queued for implementation, not yet started |
| 🛠️ | Work-in-progress | Actively being implemented |
| ⚗️ | Prototype | Implemented as a working prototype; usable, not yet hardened to full quality |
| ✅ | Implemented | Shipped and usable in ADP |

**Origin** — a MIME-type-style tag identifying where the notation comes from, in the form `<architecture-or-vendor>/<type>` (e.g. `uml/class`, `c4/context`, `archimate/business`). Tool types with no single owning standards body use the tool/author most associated with them as the vendor (e.g. `freeplane/mindmap`). This tag is what a diagram-type spec's `hierarchy.proto`-style `type` field (mime-style, per `elements.proto`) is expected to use once implemented. Editors use `editor/<id>`, the mime the backend resolves for a text file.
